# 通用编码规则（AI 可直接执行版）

> 适用：任何 Python ≥3.10 项目。零项目术语、零外部依赖。
> 配套工具：`tools/magic_string_check.py`（可单独复制到任意项目）。
> 设计原则：**规则文字管不住 AI 的手，机器检查才管用**。所以本规则只有一条强制流程 + 六条约束，
> 交付前必须跑检查器，输出为空才算完成。

---

## 0. 强制交付流程（每次改完代码都做，不做不算完成）

```bash
python tools/magic_string_check.py <你改的文件或目录>
```

- **输出为空** → 通过。
- **有任何输出** → 按 `file:line` 逐个改：能用 Enum 的改 Enum，确实要保留原样字符串的加豁免注释：

```python
if raw == "GET":  # magic-ok: HTTP 方法名，外部协议固定值
    ...
```

- 想验证检查器本身没坏：`python tools/magic_string_check.py --selftest`（应输出 PASS）。
- 测试文件（`test_*.py` 等）默认跳过——断言里的期望字符串不是状态机魔法串；
  要连测试一起查加 `--check-tests`。

**为什么要有这一步**：AI 读完"请用 Enum"的规定，写新代码时还是会顺手写 `status == "running"`。
把"跑检查器"变成交付动作，软约束才变成硬门禁。这不是可选项。

---

## 1. 有限取值用 Enum，禁止魔法字符串

状态、动作、类型、模式、等级、错误码、来源——凡能列出有限个值的，定义成 Enum，
用它声明变量、做比较、做匹配、做返回。

```python
from enum import Enum

class Status(str, Enum):          # str, Enum：需要与外部字符串互通时这样写
    RUNNING = "running"
    DONE = "done"

status: Status = Status.RUNNING
if status is Status.RUNNING:      # ✅ 比较用成员
    ...
```

```python
# ❌ 检查器会报的三类
if status == "running": ...          # E1 比较中的裸串
if kind in ("a", "b"): ...           # E1 in 集合裸串
status = "running"                   # E2 状态变量赋裸串
return "done"                        # E3 返回裸串
```

合法豁免（加 `# magic-ok: 原因`）：日志/提示文案、dict 的键名、外部协议固定值（HTTP 方法、
第三方 API 的枚举字符串）、命令行参数。模块级具名常量 `_ERR_X = "X"` 本身就是正解，不报。

---

## 2. 类型注解写全

所有函数参数、返回值（含 `-> None`）、类字段都要标注；容器带元素类型 `list[str]`、`dict[str, int]`，
禁止裸 `list`/`dict`；用 `X | None`、`list[T]`、`type X = ...` 新语法。
能描述清楚的结构不用 `Any`；确实动态的集中到一处别名并说明原因。

```python
def handle(items: list[str], *, mode: Status | None = None) -> dict[str, int]: ...
```

## 3. 明确字段用 dataclass / TypedDict

写代码时能列出所有合法键 → 就是明确字段，必须静态声明，禁止用 `dict` 拼装让下游猜键名。

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class Decision:
    action: Status
    reason: str = ""
```

只有键由外部/用户决定时才用动态字典，并注明原因。

## 4. 注释写"为什么"，不写"是什么"

每个模块、public 类/方法有一行 docstring；非显然的分支、循环、算法、绕坑处加行内注释说明
**原因/边界/不变量**，不要复述代码。

## 5. 异常内部消化，不抛穿到调用方

跨越模块边界时把异常折叠成结果对象（如 `Result`/`Response` 的失败态），带错误信息；
不要让裸异常冒出模块。健康检查类接口把失败记为 `False` 而非抛异常。

## 6. 新增能力要有默认实现 + 接线测试

- 定义协议（Protocol）就必须给一个开箱可用的默认实现；"让用户自己实现"等于没做。
- 跨模块数据流要有**接线测试**：断言上游产物被下游真实消费，不能只各测各的单元。
- 测试全绿 ≠ 功能完成；fake 通过不能替代真实后端/真实路径的验证。
- TDD：先写失败用例，再写实现让它转绿。
