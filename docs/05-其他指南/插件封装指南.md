# 插件封装指南：框架没有的功能怎么加

> 你的问题：项目需要但框架没内置的功能，怎么封装成插件？现在有没有 API 真正操作内层流程？
> 答案：**有三条路**——① 实现某个 AOP 增强器角色（how，包裹/准入/环绕/转换/兜底）；② 写一个 Lifecycle 插件订阅通知点（when，只读观察、做事不拦截）；③ 写 Program（新执行流程）或替换 Port（新外部能力）。
> 三体系正交：**Port（what，什么能力）/ AOP 增强器（how，怎么执行）/ Lifecycle 通知（when，发生了什么）**。依赖方向恒为 插件/增强器 → 装配层 → 内核，内核零依赖扩展组件。旧扩展体系（宿主 + 挂钩原语那一整套）已删除，不做兼容。

---

## 一、先说结论：三条路 + 五角色 + 16 通知点

```
① 横切"怎么执行"（how）—— AOP 五角色增强器（src/aop/）
      Prelude.run   最外层包裹，可短路整个调用
      Warden.guard  准入裁决，返回 Verdict(allowed, reason)；拒绝即拦截
      Envelope.wrap 环绕中心调用（retry 内 / timeout 外 / 资源 acquire-release / 后置记数）
      Refiner.refine 转换，产出新 Invocation（不改 State）
      Salvage.recover 异常/失败兜底；Degradation 是降级唯一裁决者
      固定顺序：Prelude → Warden → Envelope(前) → Refiner → Port call → Envelope(后) → Salvage(异常时)

② 横切"发生了什么"（when）—— Lifecycle 插件（src/hooks/lifecycle.py）
      插件契约：name + register(bus)，订阅 16 通知点之一或多个
      bus.on(通知点, fn)；收到 Notice（Invocation 只读投影 + 通知点名 + 专属 payload）
      返回值框架不消费、不能拦截改写、异常就地隔离

③ 新流程 / 新能力
      新执行流程 → Program（yield Effect）
      新外部能力 → Port（实现 Protocol + registry.register）
```

**能碰到的内层**：

- `Invocation`（AOP 统一上下文）：`effect`（当前 `Invoke`）+ `ctx`（RuntimeCtx）+ `session` + `meta`（故障具名记录含 `failed_target` 直传，非裸键容器）。请求期输入经增强器接口直传，装配期配置走构造参数私有注入。
- `Next`：增强器收到的下一层回调，最内层 `core` 由 R1 注入的 `call` 指回真实 Port（`ModelGateway.as_call`）。调 `next(inv)` 才执行 IO，不调就短路。
- `Notice`（Lifecycle 只读投影）：`hook`（通知点名）+ `projection`（Invocation 投影）+ `payload`（该通知点专属字段）。只读、不消费返回值。
- 跨调用状态由**增强器/插件实例自身**持有：熔断三态机、降级 ladder+available+按会话目标状态直接放在实例上（注册一次、长期存活，天然跨调用）；装配期配置由构造参数注入。无独立 Policy 层。

**不能碰的**：`State` 是 frozen（要改走 R7 的投影点或 AOP `Refiner` 产新 `Invocation`，不写回 `State.messages`）；增强器**不声明**调用语义或优先级——顺序由框架固定；通知订阅者**不能**拦截或改写执行流。

## 二、AOP 五角色（框架固定顺序，增强器不声明 priority）

| 角色 | 接口方法 | 直觉 | 典型用途 |
|------|---------|------|---------|
| `Prelude` | `run(inv, next) -> Result` | Middleware | 最外层包裹、可短调整个调用 |
| `Warden` | `guard(inv) -> Verdict` | Guard | 准入裁决：killswitch/幂等/舱壁/限流/熔断命中 → `Verdict(allowed=False)`，容器发 `invoke_rejected` |
| `Envelope` | `wrap(inv, next) -> Result` | Interceptor | retry 内、timeout 外、资源 acquire+finally release、成功/失败后置记数 |
| `Refiner` | `refine(inv) -> Invocation` | Pipe | 预算/上下文改写，产新 Invocation，不改 State |
| `Salvage` | `recover(exc, inv) -> Result` | ExceptionFilter | 异常/失败兜底；Degradation 选级（唯一裁决者） |

> 只有 `Invoke` 类 Effect 进 AOP 链；`Spawn`/`Suspend`/`Terminate` 走内核路径（不进增强器）。

## 三、三种典型增强器/插件

### 方式 1：Envelope 增强器 —— 包裹真实调用（最强大）

```python
from aop.protocols import Envelope
from aop.invocation import Invocation, Next, Result

class ModelRouterEnvelope(Envelope):
    """环绕真实调用：前后处理 + 命中规则可短路。"""
    name = "model_router"

    async def wrap(self, inv: Invocation, next: Next) -> Result:
        # next(inv) 才进入真实 IO（中心由 R1 注入的 call 提供）
        try:
            result = await next(inv)
        except Exception as exc:
            # 失败写 Invocation.meta 具名记录，交 Degradation(Salvage) 裁决，不在这里替别人选目标
            inv.meta["failure"] = {"failed_target": self._failed_target_of(inv), "reason": str(exc)}
            raise
        # 在 next(inv) 前后各记一笔即可统计耗时；也可在此包装 Result
        return result
```

**能做什么**：在 `next(inv)` 前后算耗时；包装 Result；按规则**不调 `next(inv)` 直接短路**（等价兜底/拒绝）；失败写 `Invocation.meta` 具名记录交 Degradation 裁决。
**要改请求内容**（预算/上下文）：用 `Refiner.refine(inv) -> Invocation` 产新 Invocation，不要在 Envelope 里塞参数。

### 方式 2：Warden 增强器（守卫）—— 准入拦截，不调用 Port

```python
from aop.protocols import Warden
from aop.invocation import Invocation, Verdict

class PIIGuard(Warden):
    """敏感信息护栏：命中就拒绝调用。"""
    name = "pii_guard"

    async def guard(self, inv: Invocation) -> Verdict:
        text = " ".join(str(m.get("content", "")) for m in inv.effect.payload.get("messages", []))
        if "身份证" in text:
            return Verdict(allowed=False, reason="检测到敏感信息")  # 容器发 invoke_rejected
        return Verdict(allowed=True, reason="")
```

### 方式 3：Lifecycle 插件（观察）—— 只读通知，异常隔离

```python
from hooks.lifecycle import Notice, LifecycleBus

class AuditLog:                       # Lifecycle 插件：name + register(bus)
    name = "audit"

    def register(self, bus: LifecycleBus) -> None:
        bus.on("after_model", self.on_model)      # 成功通知
        bus.on("tool_error", self.on_tool_error)  # 失败通知

    def on_model(self, notice: Notice) -> None:
        # Notice 是 Invocation 只读投影 + 通知点名 + 专属 payload；返回值不被消费
        ...

    def on_tool_error(self, notice: Notice) -> None:
        # 订阅者抛异常被框架就地隔离，不影响主流程
        ...
```

### 跨调用状态：实例自身持有

熔断三态机、降级阶梯这类**跨请求状态**直接放在增强器/插件实例上——注册一次、长期存活，天然跨调用；不需要独立 Policy 层，也不塞进临时容器：

```python
from aop.protocols import Salvage
from aop.invocation import Invocation, Result

class Degradation(Salvage):
    """降级裁决者：状态（ladder + available + 按会话目标）直接在本实例上（P9 四坑）。"""
    name = "degradation"

    def __init__(self, ladder, failed_target_of):
        self.ladder = ladder                      # 后端注册名，与网关注册名一致
        self.available = set(ladder)              # R3-6：故障目标永久剔除并写回
        self.by_session: dict[str, str] = {}       # B1：按 session_id 隔离，禁容器级单值
        self.failed_target_of = failed_target_of   # R3-7：故障记录携带 failed_target

    def select(self, failure_record) -> str:      # 唯一裁决者，从 Invocation.meta 故障记录选级
        failed = failure_record["failed_target"]  # B2：后端注册名，非 ("provider", name) 二元组
        self.available.discard(failed)            # 写回实例，非局部副本
        target = next((t for t in self.ladder if t in self.available), "refuse")
        return target

    async def recover(self, exc: Exception, inv: Invocation) -> Result:
        target = self.select(inv.meta["failure"])
        # 降级 target 走与 Registry 同源的 typed 路径进网关；未注册目标 TargetUnresolved 不静默回退
        return await self._call_with_target(inv, target)
```

### 装配示例（唯一的拼接方式）

```python
from aop.container import AOPContainer
from hooks.lifecycle import LifecycleBus

aop = AOPContainer()
aop.register("envelope", ModelRouterEnvelope())
aop.register("warden", PIIGuard())
aop.register("salvage", Degradation(["llm_backup", "refuse"], failed_target_of))

bus = LifecycleBus()
audit = AuditLog(); audit.register(bus)          # 通知订阅，异常就地隔离

# 增强器容器与通知总线共用同一个 Registry 实例
aop.registry = bus.registry = shared_registry

# R1 注入点：call（Port 调用），Invoke 经 aop.invoke 编排
runner = Runner(call=my_llm_port_as_call)
```

## 四、如果功能复杂到插件装不下怎么办

插件适合**横切行为**（日志 / 护栏 / 改写 / 包裹）。如果你要的是**全新的执行流程**（比如一个新的多 Agent 架构、自定义规划器），正路是写 **Program**——框架铁律是"架构即 Program"：

```python
def my_custom_flow(state: AgentState):
    """自定义流程就是一个 generator，yield Effect 声明要做什么。"""
    plan = yield Invoke(port="llm", payload={"messages": [...]})        # 声明，不执行
    results = yield [Invoke(port="tool", payload={"call": s}) for s in plan["steps"]]
    yield Terminate(output=summarize(results), reason="done")
```

Program 里只能 yield 四种 Effect：`Invoke` / `Spawn` / `Suspend` / `Terminate`。如果确实需要**新的外部能力**（比如向量库、浏览器），走 **Port 替换**——实现对应 Protocol，注册进 Registry（Port 注册名必须 ∈ `PORT_PROTOCOLS`，不可新增种类）：

```python
class MyVectorStore:
    name = "my-vector-store"
    async def upsert(self, chunks): ...
    async def search(self, vec, top_k, filters): ...
registry.register("rag", MyVectorStore())   # 协议替换，上层零改动
```

三条路的选择：

- **横切"怎么执行"** → AOP 增强器（`aop.register(role, e)`）
- **横切"发生了什么"** → Lifecycle 插件（`name` + `register(bus)`，`bus.on` 订阅）
- **新执行流程** → Program（yield Effect）
- **新外部能力** → Port（实现 Protocol + `registry.register`；Port 种类不新增，`x-*` payload 扩展键保留）

## 五、怎么写一个好增强器/插件（领域指导）

1. **职责单一**：一个增强器/插件只做一件事；要覆盖多个角色可以注册多个，但别把护栏、改写、审计混在一个类里。
2. **留名**：`name` 必填且稳定，trace 与诊断全靠它。
3. **显式声明依赖**：要用哪个 Port 就从实例构造参数显式注入；跨调用状态由实例自身持有、随注册长期存活。
4. **异常隔离**：Lifecycle 订阅者抛的异常由框架就地吞掉；写 AOP 逻辑时注意别把主流程异常吞掉——该抛出就抛出，降级意图写 `Invocation.meta` 故障记录。
5. **用具名记录而非隐式耦合**：故障写 `Invocation.meta` 的故障记录（含 `failed_target`），由 Degradation 统一裁决目标；不要直接改别人的状态或偷偷改全局/容器级单值。
6. **单一上下文**：AOP 用 `Invocation`（effect/ctx/session/meta），Lifecycle 用它的只读投影 `Notice`，不另建一套状态；元信息放 `meta` 具名键，不放裸键容器。
7. **不声明调用语义/优先级**：顺序由框架固定（AOP 五角色固定顺序），增强器只实现自己的角色接口；通知点是通知，不承诺业务语义顺序。
8. **不改运行时内核**：Effect / State / Result 是框架的确定性契约，增强器/插件只经 AOP 角色与 Lifecycle 通知交互。
9. **压缩/记忆不进内核**：上下文压缩走 R7 显式编排 + 投影点（Refiner / ctx_factory），不写回 `State.messages`。

*插件封装指南 · 按 AOP 五角色 + Lifecycle 插件重写（三体系正交：Port/AOP/Lifecycle；固定顺序、无 priority；单一上下文 Invocation/Notice；跨调用状态由实例自身持有；降级由 Degradation 唯一裁决并保四个历史修复点）*
