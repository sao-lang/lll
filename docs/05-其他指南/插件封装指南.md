# 插件封装指南：Lifecycle 通知怎么订阅

> 本指南只讲 **Lifecycle 插件**（三体系中的 **when** 体系：回答"发生了什么"，返回值框架不消费，只做事、不拦截）。
> "插件"一词在本项目专指 Lifecycle hooks，是独立的一套系统；横切执行逻辑的 **②守卫/③call 装饰器/R3 领域策略 + `ReliabilityExecutor`**（how 体系）另见[《增强器封装指南》](./增强器封装指南.md)。两者正交，不要混用术语。
> 三条正交关注点：**Port（what，什么能力）/ ②守卫·③call 装饰器·R3 领域策略（how，怎么执行）/ Lifecycle 插件（when，发生了什么）**。依赖方向恒为 插件 → 装配层 → 内核，内核零依赖扩展组件。旧扩展体系（AOP 五角色容器 + 宿主挂钩原语那一整套）已删除，五角色语义不得复辟。

---

## 一、先说清楚：插件能做什么、不能做什么

Lifecycle 是**纯通知体系**（`src/compose/notify.py`）：内核在 16 个相位把只读的 `Notice` 广播给订阅者，订阅者收到后**只做事**（记录 / 观测 / 审计 / trace）。

| 能 | 不能 |
|---|---|
| 收到 16 个相位的只读通知 `Notice` | ❌ 拦截或改写执行流（返回值框架不消费） |
| 记录日志 / 埋点 / 审计 / 接 R10 trace | ❌ 改 `State`、`Invocation` 或 Effect |
| 持有跨调用状态（实例自身） | ❌ 让通知短路调用（那是可靠性领域策略 / `ReliabilityExecutor` 的职责） |
| 订阅多个相位、一次注册长期存活 | ❌ 抛异常打断主流程（异常就地隔离） |

**一句话边界**：想知道"发生了什么" → 插件；要改变"怎么执行" → [领域策略/增强器指南](./增强器封装指南.md)。通知不是拦截通道，别拿插件当策略用。

## 二、插件契约：name + register(bus)

一个 Lifecycle 插件就是一个有 `name` 和 `register(bus)` 方法的对象，不用继承任何基类（结构化契约）：

```python
from compose import LifecycleBus, LifecyclePhase, Notice

class AuditLog:
    """审计插件：订阅多个相位，只读记录，绝不拦截。"""
    name = "audit"

    def register(self, bus: LifecycleBus) -> None:
        bus.on(LifecyclePhase.SESSION_START, self.on_session_start, name="audit-start")
        bus.on(LifecyclePhase.AFTER_MODEL, self.on_after_model, name="audit-model")
        bus.on(LifecyclePhase.INVOKE_REJECTED, self.on_rejected, name="audit-reject")

    def on_session_start(self, notice: Notice) -> None:
        ...  # 写审计日志

    def on_after_model(self, notice: Notice) -> None:
        ...  # notice.payload 带 model/error 等相位专属字段

    def on_rejected(self, notice: Notice) -> None:
        ...  # 被可靠性策略拒绝的调用也要留痕，堵审计盲区

bus = LifecycleBus()
bus.subscribe(AuditLog())    # 正规注册入口：校验 name + register 后回调 register(self)
```

`bus.subscribe(plugin)`（L170-185）校验插件有 `name` 和 `register`，然后调 `register(bus)` 让它自行订阅；缺任一项抛 `ValueError`。也可以直接用 `bus.on(phase, fn, name=...)` 挂裸回调（L135）——`name` 缺省取函数名。

## 三、Notice：只读通知载荷

`Notice` 是 frozen 数据类（`src/compose/notify.py`），`payload` 和 `meta` 在 `__post_init__` 里被冻成 `MappingProxyType`，订阅者改不动：

| 字段 | 类型 | 说明 |
|---|---|---|
| `phase` | `LifecyclePhase` | 通知相位（16 个之一） |
| `session_id` | `str` | 会话标识（从 Invocation/session 派生） |
| `port` | `str` | 能力端口名（Invoke 相位有值，其余为空串） |
| `payload` | `Mapping[str, Any]` | 该相位专属只读数据（如 `budget_check` 的 `exceeded`） |
| `meta` | `Mapping[str, Any]` | Invocation.meta 的只读快照（单一上下文，不另建状态） |

从 `Invocation` 投影的入口是 `Notice.from_invocation(phase, inv, payload=...)`（`src/compose/notify.py`）——由装配层在可靠性执行器拒绝时调用，`Notice` 本身不 import 策略实现（仅 TYPE_CHECKING 期引用，避免循环依赖）。

> 旧文档里写的 `Notice(hook / projection / payload)` 已不存在——现口径是 `phase / session_id / port / payload / meta`，字段名和函数签名以本节为准。

## 四、16 个通知点（最终口径，不得增删）

`LifecyclePhase` 是 `StrEnum`（`lifecycle.py:31-56`），16 个成员分五组：

| 分组 | 相位 | 谁发 |
|---|---|---|
| 会话/轮次 | `SESSION_START` `USER_PROMPT` `SESSION_END` `STATE_FOLD` `BUDGET_CHECK` | Runner 经 `runner_notifier` 桥接 |
| 能力调用 | `BEFORE_MODEL` `AFTER_MODEL` | R4 `ModelGateway` |
| 能力调用 | `BEFORE_TOOL` `AFTER_TOOL` `TOOL_ERROR` | Runner 经 `runner_notifier` 桥接 |
| 子 Agent | `CHILD_SPAWN` `CHILD_DONE` | Runner 经 `runner_notifier` 桥接 |
| 控制流 | `CANCELLED` `WAIT_HUMAN` `RESUMED` | Runner 经 `runner_notifier` 桥接 |
| 可靠性拒绝 | `INVOKE_REJECTED` | `ReliabilityExecutor`（经 `bus.emit` 广播 / `notify` 回调） |

已移除的相位：`before_compact` / `after_compact` / `before_invoke` / `after_invoke` / `invoke_error` / `stop` / `stop_failure` / `config_change` / `file_change`——不要用旧名字订阅（枚举里没有，写了就是无效代码）。

### 接线：Runner 相位怎么到达插件

Runner 内核零依赖 hooks，只发 `(相位名字符串, 只读投影)` 给 `notify` 回调。装配层用 `runner_notifier(bus)`（`lifecycle.py:188-212`）把这个回调桥接到总线：

```python
from compose import LifecycleBus, runner_notifier
from harness.resilience import ResilienceCapability
from runtime import Runner

bus = LifecycleBus()
bus.subscribe(AuditLog())

reliability = ResilienceCapability().install(core=my_call)   # 策略按需具名注入，此处省略
runner = Runner(
    call=reliability.as_call(),
    notify=runner_notifier(bus),   # 会话/轮次/控制流相位从这里流入总线
)
```

`runner_notifier` 把相位名归一为 `LifecyclePhase`、投影包成 `Notice`；未知相位名**安全忽略**，不让通知打断主流程。能力调用相位（`before_model` / `after_model`）由 R4 网关在 `complete()` 里直接 `bus.emit`（`gateway.py:222/249`，`after_model` 在 `finally` 里所有出口恰好发一次，`payload` 标 `error`）。`invoke_rejected` 由 `ReliabilityExecutor` 在终止拒绝时经 `bus.emit` 广播（堵审计盲区）。

## 五、三条铁律

1. **返回值不被消费**：`NoticeFn` 签名是 `(Notice) -> None`（`src/compose/notify.py`），订阅者返回什么框架都不看。想拦截执行流请用领域策略 / `ReliabilityExecutor`（见《增强器封装指南》）。
2. **异常就地隔离**：`emit()`（L149-168）逐个调订阅者，任一订阅者抛异常都被 `except` 吞掉（`noqa: BLE001`），保证一个坏插件不影响其余订阅与主流程；可选 `on_error` 钩子把异常交给装配层接 R10 trace，钩子自身异常也二次隔离。
3. **同步副作用**：`emit` 不返回 awaitable，订阅者是同步的（记录/观测/审计）。不要在里面做阻塞 IO 或 `await`——重活交给专门的 Port/回调。

## 六、怎么写一个好插件

1. **职责单一**：一个插件只做一类观测（审计、指标、trace 各一个），别把日志和护栏混在一起——护栏是可靠性领域策略的活。
2. **留名**：`name` 必填且稳定；`bus.on` 订阅时也传 `name`，trace 和 `on_error` 诊断全靠它。
3. **只读约定**：把 `Notice.payload/meta` 当只读（框架已冻结），不要试图绕过去改底层对象。
4. **异常自己兜**：虽然框架会隔离，插件内部仍应对可控失败自行处理，避免 Useful 信息全靠 `on_error` 才能看见。
5. **别做拦截的梦**：通知是"事后/事中观察"，不是"事前审批"。需要拒绝语义的是领域策略（如 `KillSwitch.is_tripped`），不是插件。
6. **跨调用状态由实例持有**：插件实例注册一次长期存活，计数器/采样缓冲直接放实例上；装配期配置走构造参数注入。

## 七、什么时候不该用插件

- 要**拒绝**一次调用 → 前置领域策略（`KillSwitch.is_tripped` / `Watchdog.detect` / `Idempotency.check_and_mark`），见《增强器封装指南》。
- 要**改写**请求内容 → A 类 `map_effect` 算子，或 R7 的上下文投影点。
- 要**包裹**调用（retry/timeout/舱位）→ `RetryPolicy.run_with_retries` / `Timeout.run_with_deadline` / `Bulkhead.run_in_slot`。
- 要**全新执行流程** → Program（yield `Invoke`/`Spawn`/`Suspend`/`Terminate`）。
- 要**新外部能力** → Port（实现 Protocol + `registry.register`，Port 种类 ∈ `PORT_PROTOCOLS` 不可新增）。
