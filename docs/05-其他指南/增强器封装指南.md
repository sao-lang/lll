# 增强器封装指南：横切"怎么执行"的功能怎么加

> 本指南只讲 **AOP 增强器**（三体系中的 **how** 体系：返回值被框架消费，能放行/拒绝/改写/包裹）。
> "插件"一词在本项目专指 **Lifecycle hooks**（when 体系：只读通知、不拦截），是另一套系统，另见[《插件封装指南》](./插件封装指南.md)。两者正交，不要混用术语。
> 三体系正交：**Port（what，什么能力）/ AOP 增强器（how，怎么执行）/ Lifecycle 插件（when，发生了什么）**。依赖方向恒为 增强器/插件 → 装配层 → 内核，内核零依赖扩展组件。旧扩展体系（宿主 + 挂钩原语那一整套）已删除，不做兼容。

---

## 一、先说结论：增强器是三条扩展路里的"横切执行"那条

```
① 横切"怎么执行"（how）—— AOP 五角色增强器（src/aop/）← 本指南
      Prelude.run    最外层包裹，可短路整个调用
      Warden.guard   准入裁决，返回 Verdict(allowed, reason)；拒绝即拦截
      Envelope.wrap  环绕中心调用（retry 内 / timeout 外 / 资源 acquire-release / 后置记数）
      Refiner.refine 转换，产出新 Invocation（不改 State）
      Salvage.recover 异常/失败兜底；Degradation 是降级唯一裁决者
      固定顺序：Prelude → Warden → Envelope(前) → Refiner → Port call → Envelope(后) → Salvage(异常时)

② 横切"发生了什么"（when）—— Lifecycle 插件（src/hooks/lifecycle.py）
      只读通知、不拦截、不改写，异常就地隔离 → 见《插件封装指南》

③ 新流程 / 新能力
      新执行流程 → Program（yield Effect）
      新外部能力 → Port（实现 Protocol + registry.register）
```

**增强器能碰到的内层**：

- `Invocation`（AOP 统一上下文）：`effect`（当前 `Invoke`）+ `ctx`（RuntimeCtx）+ `session` + `meta`（故障具名记录含 `failed_target` 直传，非裸键容器）。请求期输入经增强器接口直传，装配期配置走构造参数私有注入。
- `Next`：增强器收到的下一层回调，最内层 `core` 由 R1 注入的 `call` 指回真实 Port（`ModelGateway.as_call`）。调 `next(inv)` 才执行 IO，不调就短路。
- 跨调用状态由**增强器实例自身**持有：熔断三态机、降级 ladder+available+按会话目标状态直接放在实例上（注册一次、长期存活，天然跨调用）；装配期配置由构造参数注入。无独立 Policy 层。

**增强器不能碰的**：`State` 是 frozen（要改走 R7 的投影点或 `Refiner` 产新 `Invocation`，不写回 `State.messages`）；增强器**不声明**调用语义或优先级——顺序由框架固定；`Notice`（Lifecycle 的只读载荷）不是增强器的上下文，别把通知当拦截通道用。

## 二、AOP 五角色（框架固定顺序，增强器不声明 priority）

| 角色 | 接口方法 | 直觉 | 典型用途 |
|------|---------|------|---------|
| `Prelude` | `run(inv, next) -> Result` | Middleware | 最外层包裹、可短路整个调用 |
| `Warden` | `guard(inv) -> Verdict` | Guard | 准入裁决：killswitch/幂等/舱壁/限流/熔断命中 → `Verdict(allowed=False)`，容器发 `invoke_rejected` |
| `Envelope` | `wrap(inv, next) -> Result` | Interceptor | retry 内、timeout 外、资源 acquire+finally release、成功/失败后置记数 |
| `Refiner` | `refine(inv) -> Invocation` | Pipe | 预算/上下文改写，产新 Invocation，不改 State |
| `Salvage` | `recover(exc, inv) -> Result` | ExceptionFilter | 异常/失败兜底；Degradation 选级（唯一裁决者） |

> 只有 `Invoke` 类 Effect 进 AOP 链；`Spawn`/`Suspend`/`Terminate` 走内核路径（不进增强器）。
> 角色名是有限集合，用 `aop.Role` 枚举（`Role.PRELUDE/WARDEN/ENVELOPE/REFINER/SALVAGE`），不要用裸字符串。

## 三、三种典型增强器

### 方式 1：Envelope 增强器 —— 包裹真实调用（最强大）

```python
from aop import Envelope, Invocation, Next
from aop.invocation import FaultRecord
from runtime import Result

class ModelRouterEnvelope(Envelope):
    """环绕真实调用：前后处理 + 失败写具名故障记录。"""
    name = "model_router"

    def __init__(self, failed_target_of):
        self._failed_target_of = failed_target_of  # 构造注入，R3-7 故障必带 failed_target

    async def wrap(self, inv: Invocation, next: Next) -> Result:
        try:
            result = await next(inv)          # next(inv) 才进入真实 IO
        except Exception as exc:
            inv.write_fault(FaultRecord(       # 具名故障记录，交 Degradation(Salvage) 裁决
                reason=str(exc),
                failed_target=self._failed_target_of(inv),
            ))
            raise                              # 别在这里替别人选目标
        return result
```

**能做什么**：在 `next(inv)` 前后算耗时；包装 Result；按规则**不调 `next(inv)` 直接短路**（等价兜底/拒绝）；失败写具名故障记录交 Degradation 裁决。
**要改请求内容**（预算/上下文）：用 `Refiner.refine(inv) -> Invocation` 产新 Invocation，不要在 Envelope 里塞参数。

### 方式 2：Warden 增强器（守卫）—— 准入拦截，不调用 Port

```python
from aop import Warden, Invocation, Verdict

class PIIGuard(Warden):
    """敏感信息护栏：命中就拒绝调用。"""
    name = "pii_guard"

    async def guard(self, inv: Invocation) -> Verdict:
        text = " ".join(str(m.get("content", "")) for m in inv.effect.payload.get("messages", []))
        if "身份证" in text:
            return Verdict(allowed=False, reason="检测到敏感信息")  # 容器发 invoke_rejected
        return Verdict()
```

### 方式 3：Salvage 增强器（降级裁决）—— 跨调用状态由实例自身持有

```python
from aop import Salvage, Invocation
from aop.invocation import FaultRecord, RoutingTarget
from runtime import Result

class Degradation(Salvage):
    """降级裁决者：状态直接在本实例上（P9 四坑）。"""
    name = "degradation"

    def __init__(self, ladder):
        self.ladder = ladder                       # 后端注册名，与网关注册名一致
        self.available = set(ladder)               # R3-6：故障目标永久剔除并写回
        self.by_session: dict[str, str] = {}       # B1：按 session_id 隔离
        self._call_with_target = None              # 装配时注入：按 target 调用网关的回调

    async def recover(self, exc: Exception, inv: Invocation) -> Result:
        fault: FaultRecord | None = inv.fault()
        failed = fault.failed_target if fault else ""
        self.available.discard(failed)             # 写回实例，非局部副本
        target = next((t for t in self.ladder if t in self.available), "refuse")
        inv.write_routing_target(RoutingTarget(target=target, reason=fault.reason if fault else ""))
        return await self._call_with_target(inv, target)   # 未注册目标 TargetUnresolved 不静默回退
```

### 装配示例（增强器的唯一拼接方式）

```python
from aop import AOPContainer, Role
from harness.model import ModelCapability

cap = ModelCapability(llm=my_llm_port)
aop = AOPContainer(cap.gateway().as_call())       # core 必填：中心 Port 调用
aop.register(Role.ENVELOPE, ModelRouterEnvelope(failed_target_of))
aop.register(Role.WARDEN, PIIGuard())
aop.register(Role.SALVAGE, degradation)

# R1 注入点：call 槽吃下整条增强链，Runner 不感知 AOP 存在
runner = Runner(call=aop.as_call())
```

要同时接 Lifecycle 通知（审计/观测），用 `runner_notifier(bus)` 桥接 `Runner(notify=...)`，玩法见[《插件封装指南》](./插件封装指南.md)。**增强器与插件是两套体系，各自独立装配，只在装配层汇合。**

## 四、如果功能复杂到增强器装不下怎么办

增强器适合**横切行为**（护栏 / 改写 / 包裹 / 兜底）。如果你要的是**全新的执行流程**（比如一个新的多 Agent 架构、自定义规划器），正路是写 **Program**——框架铁律是"架构即 Program"：

```python
def my_custom_flow(state: AgentState):
    """自定义流程就是一个 generator，yield Effect 声明要做什么。"""
    plan = yield Invoke(port="llm", payload={"messages": [...]})        # 声明，不执行
    results = yield [Invoke(port="tool", payload={"call": s}) for s in plan["steps"]]
    yield Terminate(output=summarize(results), reason="done")
```

Program 里只能 yield 四种 Effect：`Invoke` / `Spawn` / `Suspend` / `Terminate`。如果确实需要**新的外部能力**（比如向量库、浏览器），走 **Port 替换**——实现对应 Protocol，注册进 Registry（Port 注册名必须 ∈ `PORT_PROTOCOLS`，不可新增种类）：

```python
class MyVectorStore:
    name = "my-vector-store"
    async def upsert(self, chunks): ...
    async def search(self, vec, top_k, filters): ...
registry.register("rag", MyVectorStore())   # 协议替换，上层零改动
```

三条路的选择：

- **横切"怎么执行"** → AOP 增强器（`aop.register(Role.X, e)`）← 本指南
- **横切"发生了什么"** → Lifecycle 插件（`name` + `register(bus)`，`bus.on` 订阅）→ 《插件封装指南》
- **新执行流程** → Program（yield Effect）
- **新外部能力** → Port（实现 Protocol + `registry.register`；Port 种类不新增，`x-*` payload 扩展键保留）

## 五、怎么写一个好增强器（领域指导）

1. **职责单一**：一个增强器只做一件事；要覆盖多个角色就注册多个，别把护栏、改写、兜底混在一个类里。
2. **留名**：`name` 必填且稳定，trace 与诊断全靠它。
3. **显式声明依赖**：要用哪个 Port 就从实例构造参数显式注入；跨调用状态由实例自身持有、随注册长期存活。
4. **别吞主流程异常**：Envelope/Warden 该抛出就抛出，降级意图写 `Invocation.meta` 的具名故障记录（`inv.write_fault`），由 Degradation 统一裁决；不要直接改别人的状态或搞容器级单值。
5. **用具名记录而非隐式耦合**：故障经 `FaultRecord(reason, failed_target)` 传，目标经 `RoutingTarget` 传，别塞裸键。
6. **单一上下文**：AOP 用 `Invocation`（effect/ctx/session/meta），不另建一套状态；`Notice` 是 Lifecycle 的只读投影，不属于增强器。
7. **不声明调用语义/优先级**：顺序由框架固定（五角色固定顺序），增强器只实现自己的角色接口。
8. **不改运行时内核**：Effect / State / Result 是框架的确定性契约，增强器只经 AOP 角色交互。
9. **压缩/记忆不进内核**：上下文压缩走 R7 显式编排 + 投影点（Refiner / ctx_factory），不写回 `State.messages`。
