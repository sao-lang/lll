# 设计文档一致性审查报告

> 历史记录：本文记录 2026-11-17 某次审查结论。文中「8 种 action 只有 4 种生效」等发现已被后续设计修正采纳（见总设计附录 E、R2 §5.5）；当前状态以《设计完整性重新自查-20261117》为准。

> 审查对象：AGENT-总设计 + R1~R13 模块文档 + 流程规范。
> 方法：机器扫描（旧编号/门禁key/字段/签名/数量表述）+ 人工核对已实现代码（R1/R2）。
> 目的：找出"设计漂移"——文档说一套、代码做一套，或文档之间互相矛盾——这是导致后续改设计就得重构已实现功能的根因。

## 二·补：插件能力实测发现的运行时缺陷（更严重，已修）

用户追问"框架没有的功能怎么封装成插件、有没有 API 操作内层流程"时，实测发现 R1↔R2 集成有 3 个**比文档漂移更严重**的运行时 bug：

| # | 缺陷 | 后果 | 修复 |
|---|------|------|------|
| E1 | R1 `_execute` 用 `getattr(outcome,'abort',False)` 判定，而 `Decision.abort` 是类方法（truthy） | **所有 hook 返回的 Decision 都被误判为 abort**，插件体系整体失效 | 改按 `action` 字段判断，排除 callable |
| E2 | around 中心 invoke 调一次 Port，R1 拿到 continue 后又用原始 effect 调一次 | 插件改写失效 + **工具副作用执行两次**（灾难性） | core 把 invoke 的 Result 装进 `Decision.value`，R1 直接采用不重复调 |
| E3 | R1 读 `outcome.data`，Decision 实际字段是 `value` | 裁决结果永远读不到 | 统一为 `value` 字段 |

另发现**设计宣称但代码空壳**：8 种 Decision action 中只有 continue/deny/abort/fallback 真生效；rewrite（对执行无效）、degrade、retry、ask 是空壳（属 R3/R4/R9 未实现模块）。详见[《插件封装指南》](../插件封装指南.md)。

修复有回归测试：`tests/r2/test_extensibility.py` + `tests/r1/test_dispatch_verdict.py`。

## 三、防复发：设计稳定性门禁

本次审查的缺陷有一个共同模式：**设计文档被改动后，与已实现代码脱节，但没有任何机制拦截**。
为此新增 **G5 设计稳定性门禁**（见 `docs/03-流程与规范/设计稳定性门禁.md` + `tests/tools/contract_lock.py`）：
- 锁定 R1/R2 已实现模块的公共契约符号与关键签名；
- 任何设计文档修改若改变了这些契约，门禁立即失败，强制走"契约变更评审"；
- 防止"改设计 → 已实现功能被迫重构"的危险。
