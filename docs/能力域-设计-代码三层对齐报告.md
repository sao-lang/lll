# 能力域 → 设计 → 代码：三层对齐报告（2026-11-17）

> **用户期望（本次工作的验收标准）**：能力域尽量全面 → 设计覆盖能力域 → 代码按设计实现。
> **方法**：三个独立实证层——① 精确统计能力域全景 169 项；② 逐项判定 R1~R13 设计文档深度；
> ③ 逐项核对 src/ 代码实现。两层判定由独立子代理完成，关键结论已用 Bash 抽查复核。
> 本报告**不引用**旧自查报告作为结论来源。已发现的问题已就地标注在各设计文档头部。

## 0. 执行摘要（先看结论）

| 层 | 统计 | 结论 |
|---|---|---|
| 能力域 | 18 域 / **169 项**（文档标题写"约160"，实际 169） | 清单本身相当全面，判定口径明确（"缺失会导致生产环境出错/失控/不可查/不可恢复即为必备"） |
| 设计覆盖 | 169 项中 **设计充分 115 / 薄弱 46 / 缺失 8** | 大部分有设计，但 46 项只有"功能名+一句话机制"，照着写不出代码 |
| 代码实现 | 169 项中 **已实现 33 / 部分 61 / 未实现 75** | 真正完整落地的只有 33 项（19.5%），且几乎全在 A/B/C/J/O/P/Q 少数域 |

**三层 gap 的本质**：能力域清单是"全"的；设计层在横切细节（算法/参数/状态机）和 SSE 类能力上塌了一角；
代码层只覆盖了 R1~R4 四个模块——**75 项未实现中绝大多数属于 R5~R13，那些模块的源码包根本不存在**。

**一句话回答"是不是又检查出实现不完整"**：是，而且这次能量化——169 项里 61 项只有半成品、75 项全无。
但要注意，"未实现"不等于"设计漏了"：绝大多数是**设计写了、代码没写**（R5~R13 全部停留在设计态），
真正"设计就缺失"的只有 8 项（见 §3）。

**61 项部分实现**的典型缺口：
- **C7 流式**：仅 `LLMPort.stream` 签名（`src/hooks/protocols.py:53`）+ fake（`tests/r4/fakes.py`），无网关编排/真后端/工具事件。

- **R3 成本告警**：CostGuard 有硬闸，无预算耗尽告警通道。

**75 项未实现**的主因：R5~R13 的源码包（tools/rag/context/cognition/archs/security/api…）全部不存在。

## 4. 三层对照：gap 归因

把每层判定交叉，169 项可分为四类：

| 类型 | 数量（估） | 含义 | 处置 |
|---|---:|---|---|
| **设计充分 + 已实现** | ~33 | 已闭环（R1~R4 核心） | 保持；补文档同步（见问题标注） |
| **设计充分 + 未实现** | ~82 | 设计已备、等待编码（R5~R13 主体） | **按设计排期实现**——不需要先补设计 |
| **设计薄弱 + 部分实现** | ~30 | 代码有壳、设计有洞 | 先补设计细节再补代码（C7 流式、A5 取消、M4 事件流等） |
| **设计缺失** | 8 | 连设计都没有 | 先做设计（B10/B11/G9/A5/J10/N8/Q10/D13） |

**对用户期望的直接回答**：
- "能力域尽量全面" → ✅ 已达成（169 项、18 域，判定口径明确）。
- "设计覆盖能力域" → ⚠️ 部分达成（115 项充分，46 项薄弱，8 项缺失）。**不是全覆盖**。
- "代码按设计实现" → ❌ 远未达成（33/169 完整实现）。**主要不是代码写错，而是 82 项设计好的代码还没写**。

## 5. 按用户关注点：SSE/流式能力专项

用户点名"SSE 能力做得不完整"。三层状态：

| 层 | C7 流式输出 | A5 取消传播 | M4 事件流 |
|---|---|---|---|
| 能力域 | 有定义："stream() 逐 token + 工具事件 + 取消传播" | 有定义："Cancellation 信号向子 effect/流递归传播" | 有定义："标准化事件流供平台消费" |
| 设计 | 只给 `LLMPort.stream()` 签名；编排层空白（详见《流式输出设计说明》） | **完全缺失**：R1 无 Cancellation 信号设计；R12 race 算子却引用了它 | 只有 `subscribe(topic, since)` 读侧签名，无事件 schema/背压/投递语义 |
| 代码 | 协议签名 + fake 逐块产出；`ModelGateway` 无 `stream()`；无真后端 | src 无任何 cancel 相关；仅 fake 测试 `aclose()` 可中断 | 协议签名存在，零实现 |

**结论**：用户判断正确——SSE 链路是"能力域写了、设计只写了一半、代码只有契约和 fake"的典型三层塌陷。
补齐需要：R1 加 Cancellation 内核设计 → R4 补 ModelGateway.stream() 编排设计 → 代码层实现网关流式 + 真 SSE 适配器 + 事件流发布端。

3. **M4 事件流**：在 R10/R11 定义事件 schema、topic 命名、背压、投递保证。

**P1 — 设计充分但没代码的 82 项**：按模块排期实现（R5→R13），每项已有 API 签名可直接开工。
