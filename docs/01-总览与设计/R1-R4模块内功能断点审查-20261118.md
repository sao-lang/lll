## 维度 2：4 种 HookMode 的执行 + 插件事件匹配

bus.py:198-224 四种 mode（OBSERVE/GUARD/TRANSFORM/AROUND）**全部有执行分支** ✅。

但插件订阅的事件与实际 emit 的事件**严重错配**：

| 插件（R3） | 订阅事件 | 生产代码谁 emit | 判定 |
|-----------|---------|----------------|------|
| KillSwitch/Watchdog/Idempotency/Bulkhead/RateLimit/CircuitBreaker/Degradation | `before_invoke` | 上层 dispatch 回调（测试/demo 手搓 bus.emit） | ⚠️ 依赖外部 composition root（R12，本轮排除） |
| RetryPolicy | `before_invoke` | 同上 | ⚠️ 同上 |
| **BudgetGuard** | `before_model` | **全项目生产代码零 emit**（仅测试 1 处） | 🔴 **R1~R4 断点**：插件挂了但事件永不触发 |
| CircuitBreaker 的 AROUND 后置 | `after_invoke` / `invoke_error` | **全项目零 emit** | 🔴 **R1~R4 断点**：熔断结果无法回喂计数，三态机在真实链路里不翻转 |

证据：`grep -rhn "emit(" src tests | grep -oE 'emit\("...`'` → 只有 `before_invoke`(9) 和 `before_model`(1,测试)。

## 维度 5：R1↔R2↔R3↔R4 模块间接线

依赖方向（src 生产代码 import 实证）：
```
runtime ← hooks ← harness/resilience(R3) ← harness/model(R4) ← ports/adapters
```
无循环依赖 ✅，分层正确 ✅。

但**没有任何生产代码把四者串成可运行 Agent**：
- R1 Runner 只调注入的 `dispatch`/`call` 回调（runner.py:323），不直接接 bus/gateway；
- `src/` 中 `Effect → LLMRequest` 适配器**不存在**（grep 无任何生产代码构造 LLMRequest 去调 gateway）；
- R3 插件通过 bus.on() 挂载，但 composition root（R12）未实现。

⚠️ 这属于**模块间接线缺失**，此前已登记总设计 B.1.3（R12 装配层）。按用户"只看 R1~R4 模块关系"——这是 R1-R4 之间的断点，但根因是缺一个装配层，不是四个模块内部坏了。

## 维度 6：多后端切换（承接上一问题）

`OpenAICompatLLM` 一个实例 = 一个固定 base_url/api_key（llm.py:35-42）；
`_payload` 用 `req.model or self._model`（:67）——模型名只改 body 字段，不改端点。
无"模型名→端点/密钥"注册表。

🔴 **R1~R4 实质断点**：跨服务商降级无效（与维度 1 的 DEGRADE 断点是同一条链）。

## 维度 7：模块内核心功能可达性（确认无断点）

逐项核查均有测试+demo+门禁覆盖：
- R1：解释循环、Effect 展开、fold、预算硬限、事件溯源、checkpoint（async 已修）
- R2：四 mode 编排、8 action 载体、留名、异常隔离、registry
- R3：失败分类、退避、熔断三态机内部逻辑、降级阶梯选择、限流、舱壁、幂等、watchdog、killswitch、五插件 priority 排序
- R4：缓存（精确+语义+可换 store/embedder）、结构化校验修复、成本归因+硬闸、流式事件、换 LLMPort

注意："内部逻辑正确" ≠ "接上真实链路"——熔断三态机逻辑对，但 after_invoke/invoke_error 不 emit，真实链路里不翻转（维度 2）。
