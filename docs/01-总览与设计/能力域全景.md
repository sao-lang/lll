# 能力域全景（完整 Harness 18 域 / 169 项）

> 状态：设计提案 v1.0（已按自查补齐，待办见 AGENT 总设计附录 B.1）。配套[《AGENT 总设计》](./AGENT-总设计.md)。
> 本文是**能力完整性**的权威清单：回答"完整 harness 到底要哪些能力"，逐项标注归属层、承载形态、模块映射。
> 判定口径：**只要一个能力缺失会导致 Agent 在真实生产环境里出错、失控、不可查或不可恢复，它就是 harness 必备能力**，无论框架是否已有。
> **口径说明（2026-11-21 算子核心重构）**：本表是**需求侧清单**，169 项一项不删、一项不改名；"承载形态"是二维分类的第二维（第一维＝能力，做什么；第二维＝承载形态，怎么实现），统一按①组合算子 / ②领域策略 / ③call 装饰器 / ④notify 观察 / ⑤Port 接入 / ⑥组件 / ⑦内核机制 七种重标。"算子"仅指①组合算子（Program→Program），retry/timeout/熔断/降级/沙箱/工具/追踪都是能力、不是算子。

---

## 0. 怎么用这份清单

- 每个域是一组内聚能力；每项能力标注 **归属层**（L0 内核 / L1 插件 / L2 架构 / L3 接入）、**承载形态**（①组合算子 / ②领域策略 / ③call 装饰器 / ④notify 观察 / ⑤Port 接入 / ⑥组件 / ⑦内核机制）、**现有映射**（对应现行 R1~R13 模块的哪块，`—` 表示尚无落点）。
- 承载形态口径（7 承载形态，按 agent 运行周期排列）：①组合算子＝`Program→Program`，装配期，狭义"算子"仅指此类、框架核心（seq/par/race/map_effect/fallback/retry 流程级 + loop_until/branch_value 回注值驱动；原 branch/loop/map_state/gate 因依赖不存在的 state port 已删除）；②领域策略＝`check/observe` 实例跨调用存活（熔断/限流/舱壁/幂等/降级阶梯/watchdog/killswitch）；③call 装饰器＝`CallFn→CallFn` 运行期（调用级 retry/timeout/危险路由/注入检测）；④notify 观察＝R1 现有 notify 回调只读（链路追踪/审计/指标/成本归因，16 相位保留为 notify 相位口径）；⑤Port 接入＝Protocol+Registry（工具/沙箱/LLM/记忆/RAG/Store）；⑥组件＝普通类/函数（切分/嵌入/重排/改写/规划器/上下文四链）；⑦内核机制＝R1 内部（预算/终止/挂起/checkpoint/取消）。旧"三体系正交（Port/AOP/Lifecycle）"口径已被取代：AOP 五角色拆分进②③，LifecycleBus 由④取代。上下文压缩不是内核能力，走⑥组件/投影点（见 F3/F7）。
- **现有映射为 `—` 的项是能力缺口**，优先补齐。
- 深度详设见各 R 模块文档（`docs/02-模块详设/Agent/`）；本文每项给出"核心机制"一句话，用于判断该项是否已覆盖。
- 下表"现有映射"列的 M1~M11 是重写前的旧模块编号，历史溯源用；现行以 R 模块为准。
