## 2. 维度②：异步场景（重点发现）

判断标准（据总设计 §2 "Runner 是唯一 async IO 汇聚点"）：**协议实现涉及外部 IO 且会被 Runner 异步路径调用 → 应 async**。

### 2.1 已正确处理（async）✅
LLMPort / RAGPort / MemoryPort / SandboxPort / EvalPort / HumanPort / MCPPort / StorePort.save? / Embedder / VectorStore / Retriever / Offloader / Hook / 认知策略（Intent/Planner/Reflect/...）/ CachePort v1.4。

### 2.2 当前模块（R1/R2 代码）里的真问题 ⚠️

| 协议 | 现状 | 问题 | 建议 |
|------|------|------|------|
| **EventStore.save/load**（R1） | 同步；`Runner.step()`(async) 里同步调 `_store.save(...)` | checkpoint 落 DB/Redis 是生产刚需，同步会阻塞事件循环 | 改 async：`async def save/load`，Runner.step 用 await；`Runner.load` 也要改 async（API 变更） |
| **StorePort.save/load**（R2） | 同步；R3 Idempotency 的 dedup_store、R7 卸载目标 | dedup store 落 Redis/DB 是典型场景，同步阻塞 | 改 async：`async def save/load` |
| **AuditPort.record**（R2） | 同步 | 审计落盘/远程（append-only+哈希链）是 IO | 改 async：`async def record` |

### 2.3 设计合理、不改 async（有意为之）✅

| 协议 | 为何同步是对的 |
|------|--------------|
| TelemetryPort.span/metric/log（R2） | **OTel 标准做法**：同步 API + 实现内部异步批量导出；span 是上下文管理器必须同步 |
| EventStreamPort.subscribe（R2） | 返回 `AsyncIterator`（PEP525 用 def 声明），消费侧 async ✅ |
| MCPPort / HumanPort / Guardrail.check | guard 在关键路径，同步 API 更可控；内部远程调用由实现异步消化 |
| SkillPort.discover/body、Splitter、CompactionPolicy、Reranker（本地推理） | 纯计算/本地文件，无需 async |

### 2.4 后续模块（R6/R9/R10 设计态，不现在改，已标注）

- R6 `Reranker.rerank` 同步：本地 cross-encoder OK；若实现用远程 rerank API 需 async → 设计时按实现选。
- R9 `Guardrail.check`/`InjectionDetector.inspect` 同步：模型判别若走网络，实现内部应异步预热+本地判定。
- R10 `Projection.project` 同步：读模型投影是纯计算，OK。

## 3. 维度③：外部工具可注入（重点发现）

判断标准：**协议实现需要外部系统（DB/Redis/向量库/API/文件）→ 必须把 client/store 抽象成可注入协议，且框架自带默认实现**。

### 3.1 已正确抽象 ✅
- `CachePort` + `CacheStore`（本轮 v1.4）+ `CacheEmbedder`（本轮）：三层，Redis/DB/向量模型都可换，默认 InMemory/difflib
- `VectorStore`（R6）：可换 PgVector，默认内存
- `StorePort`/`MemoryPort`（R2/R7）：可换存储后端
- `LLMPort`（R2）：可换后端，默认 OpenAICompat（R4）
- `EventStore`（R1）：可换 checkpoint 后端，默认 InMemory

### 3.2 当前模块需补注入入口 ⚠️

| 协议/组件 | 现状 | 问题 | 建议 |
|----------|------|------|------|
| **TelemetryPort**（R2） | 无 exporter 注入入口 | 接 OTel collector/jaeger 时，导出目标（endpoint/协议）无协议化入口，实现者各搞各的 | 补 `TelemetryExporter` 协议（export(records)），默认 in-process；实现内部异步批量。属 R2 契约，R10 实现 |
| **AuditPort**（R2） | 无 store 注入入口 | 审计落哪（文件/DB/远程）无抽象 | 补 `AuditStore` 协议（append(event)），默认内存/文件；结合 2.2 的 async |

### 3.3 后续模块（设计态，登记待办，不现在改）
- R9 SandboxPort：沙盒后端（进程/容器）的选择应可注入 → R9 设计时定
- R6 Retriever/Reranker：若依赖外部检索服务，client 应可注入 → R6 设计时定
- R10 Projection：读模型存储（内存/DB）可注入 → R10 设计时定
