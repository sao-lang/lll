## 1. 重构目标与根因

### 1.1 根因（三个已核实的事实）

1. **声明与执行脱节**：`LifecycleEvent`（`src/hooks/types.py:72-106`）声明 21 个事件，全 src 零消费、零 dispatch；真正跑的只有 6 个 invoke 级扩展点。
2. **6 个 invoke hook 语义过载**：它们承载 BAIL/WATERFALL/AROUND/PARALLEL 五种语义（`src/hooks/v5.py:49-56`），且只覆盖单个 Effect 的 dispatch→call 窗口；CHILD/END/WAIT_HUMAN 走快路径完全绕过。
3. **依赖倒置**：内核契约被可选插件（R3）的需求绑架；插件不是必需品，应先定内核再定插件。

### 1.2 目标（三体系正交）

| 体系 | 回答 | 承载 | 返回值 |
|---|---|---|---|
| **Port** | what（什么能力） | 14 个 Protocol + Registry | 能力结果 |
| **AOP Enhancer** | how（怎么执行） | 5 角色增强器 | 被消费：放行/拒绝/改写/包裹 |
| **Lifecycle hooks** | when（发生了什么） | 16 个通知点 | 不消费，只做事 |

依赖方向恒定：**插件/增强器 → 装配层 → 内核**；内核零依赖扩展组件。

### P3 · 新增 AOP Enhancer 体系（独立命名，非 NestJS）

**现状证据**：R3 插件以 `Plugin.apply(host)` 订阅 6 个 invoke hook；用户无统一增强器入口。

**改法**：建 `src/aop/`（新包），五角色 + 统一上下文：

```python
@dataclass(frozen=True)
class Invocation:
    effect: object          # 具体为 Invoke（见 P5）
    ctx: object             # RuntimeCtx
    session: object         # Session
    meta: Mapping[str, object]

Next = Callable[[Invocation], Awaitable[Result]]

class Prelude(Protocol):    # 最外层包裹（NestJS Middleware）
    name: str
    async def run(self, inv: Invocation, next: Next) -> Result: ...

class Warden(Protocol):     # 准入（Guard）
    name: str
    async def guard(self, inv: Invocation) -> Verdict: ...   # Verdict(allowed, reason)；安全域四态用 SafetyVerdict（D-1）

class Envelope(Protocol):   # 环绕（Interceptor）
    name: str
    async def wrap(self, inv: Invocation, next: Next) -> Result: ...

class Refiner(Protocol):    # 转换（Pipe）
    name: str
    async def refine(self, inv: Invocation) -> Invocation: ...

class Salvage(Protocol):    # 异常兜底（ExceptionFilter）
    name: str
    async def recover(self, exc: Exception, inv: Invocation) -> Result: ...
```

- 执行顺序框架固定：`Prelude → Warden → Envelope(前) → Refiner → Port call → Envelope(后) → Salvage(异常时)`；增强器**不声明 priority**（消除 R7 的 priority blocker（讨论稿 R7-B2））。
- AOP 容器 `AOPContainer`：按角色分组注册、按固定顺序编排；异常/拒绝时**强制发 `invoke_rejected` 通知**（堵审计盲区）。
- 只有 `Invoke` 类 Effect 进 AOP 链（见 P5）；Spawn/Suspend/Terminate 走内核路径。
- 上下文**单一**：`Notice` 是 `Invocation` 的只读投影，不另建一套状态。

**涉及代码**：`src/aop/`（新建：`container.py` / `protocols.py` / `invocation.py`）、`src/runtime/runner.py`（call 槽接入容器）、`src/harness/resilience/*`（见 P4）。
**涉及文档**：`AGENT-总设计.md`（新增 AOP 章节）、新建 `docs/02-模块详设/Agent/R3-AOP增强体系.md` 或并入 R2、`R12-内置架构与组合.md` §retry 算子描述、`能力域全景.md`（所有 guard/around 类形态改标 AOP 角色）。

### P4 · R3 九个插件迁入 AOP（Degradation 见 P9）

**现状证据**：`ResilienceCapability.install(host)`（`src/harness/resilience/capability.py:53-57`）把插件 tap 到 6 个 hook；插件状态在实例上（三态机/ladder/令牌桶/幂等表）。

**改法**：插件**保留一等身份**（name + 实例状态 + 构造注入依赖），只把实现接口从 `apply(host)` 换成对应 AOP 角色：

| 插件 | 原 hook | 新角色 | 说明 |
|---|---|---|---|
| KillSwitch | before_invoke | Warden | 标志置位 → `Verdict(allowed=False)` |
| Watchdog | before_invoke | Warden | 循环命中 → 拒绝 + `invoke_rejected` |
| Idempotency | before_invoke | Warden | 幂等键命中 → 拒绝 |
| RateLimit | before_invoke | Warden | 令牌不足 → 拒绝 |
| CircuitBreaker.check | before_invoke | Warden | OPEN/半开超额 → 拒绝 |
| RetryPolicy | around_invoke | Envelope | 循环调 next，失败退避 |
| Timeout | around_invoke | Envelope | wait_for 包 next |
| Bulkhead | before_invoke + releases | Envelope | acquire + try/finally release（替掉 scope.releases） |
| CircuitBreaker.observe | after_invoke/invoke_error | Envelope | 后置记数，状态仍在实例 |
| BudgetGuard | transform | Refiner | 不改 State，产新 Invocation |
| Degradation | settle | **见 P9（不得按本表简单迁移）** | 降级链路历史返工多次，须单独设计 |

- **删除**：`Signal`/`SignalKind`/`settle`/`sticky_targets` 那套信号链——**但降级语义不得丢失**，其正确迁移方案见 P9（本节只处理非降级的九个插件（CircuitBreaker 拆 check/observe 两角色仍算一个插件））。
- `ResilienceCapability.install` 改为向 `AOPContainer` 注册各角色；`extra_plugins` 的契约从 `Plugin` 改为五角色之一。

**涉及代码**：`src/harness/resilience/breaker.py:124-128`、`defenses.py:181-183,243-245,294-296,362-364,394-396,453-455`、`retry.py:69-71`、`timeout.py:48-50`、`capability.py`。

### P5 · EffectKind 拆成 tagged union + Disposition

**现状证据**：`EffectKind` 6 值混三种语义（`runtime/types.py:84-96`）；消费点散在 `fold.py:105-118,157-165`、`runner.py:343,472,491,503,506,514`、`gateway.py:133`、`retry.py:113`。

**改法**：Effect 改为类型级联合，Runner 用 `match` 分派：

```python
class Disposition(str, Enum):
    INVOKE = "invoke"; SPAWN = "spawn"
    SUSPEND = "suspend"; TERMINATE = "terminate"

@dataclass(frozen=True)
class Invoke:                       # 唯一走 AOP
    port: str                       # ∈ PORT_PROTOCOLS，装配期校验
    payload: EffectPayload
@dataclass(frozen=True)
class Spawn:
    program_factory: Callable[[], Program]
    state: AgentState
@dataclass(frozen=True)
class Suspend:
    question: str
    options: tuple[str, ...]
@dataclass(frozen=True)
class Terminate:
    output: object
    reason: str

Effect = Invoke | Spawn | Suspend | Terminate
```

- `SKILL` 并入 `Invoke(port="skill")`；`fold` 按 port 决定写 assistant/tool 消息还是 `last_skill`。
- 新增 RAG/Memory 等能力只需 `Invoke(port="rag")`，内核零改动。
- **不做运行时兼容层**；提供离线迁移工具把旧快照的 `kind` 字段一次性转为新形态（迁移工具由 P5 自身交付）。

**涉及代码**：`src/runtime/types.py`（Effect 定义）、`fold.py`（三分支重写）、`runner.py`（match 分派）、`interpreter.py`（Effect 校验）、`src/harness/model/gateway.py:133`、`src/harness/resilience/retry.py:113`、**所有 Program 的 yield 写法**（demos + tests）。

### P8 · 被否决方向（防止执行时回退）

执行中**不得**重新引入以下已被明确否决的设计：

1. 把 lifecycle hook 做成只读观察通道——它是通知型 hook，不是埋点；
2. 把插件降成裸函数装饰器——插件必须保持一等身份（name + 实例状态 + 构造注入）；
3. 用插件需求反推内核——依赖方向恒为 插件→装配→内核；
4. 用"替换 6 个 invoke hook"的思路设计 Lifecycle——它是独立体系，不是替代品；
5. 给业务语义相位配 BAIL/裁决语义——通知型不拦截；
6. 把压缩/记忆提炼塞进执行循环——非确定 IO 破坏回放。

### P9 · 降级链路（最高风险，单独设计）

**背景**：R3 历史上围绕降级反复返工。本规格绝不能把 Degradation 当作"贴个 Salvage 标签"处理——须先保住既有已修复的语义，再换宿主。

**历史踩过的四个坑（均有代码/文档留痕，迁移时必须逐条不丢）**：

1. **B1 · 全局单槽串味**：降级目标原本放全局单槽，多会话互相污染 → 改为按 `session_id` 隔离的 `_sticky_targets`（`v5.py:317,471`）。新方案若用单一的容器级 `current_target`，此坑立刻重现。
2. **B2 · failed_target 用错标识**：降级的 `failed_target` 必须是**降级阶梯里的后端注册名**，不是熔断维度二元组 `("provider", name)`，否则网关切不到后端、静默回退默认模型（`breaker.py:60-67` + R3 详设 §6.8，`gateway.py:152` 明确"未注册目标 → TargetUnresolved，绝不静默回退"）。
3. **R3-6 · available 不写回导致选级空心化**：故障目标必须**永久从实例 `available` 剔除并写回**，不能只在局部副本 discard；否则 backup 故障后会重新选回 primary，永远到不了 REFUSE（`defenses.py:104-117`）。
4. **R3-7 · 失败目标没带出来**：retry 耗尽 / timeout 的降级信号必须携带 `failed_target`（由构造注入的 `failed_target_of(effect)` 派生），settle 才能据此剔除；只发 reason 不选目标会剔除失败（`retry.py:94-97`、`timeout.py:58-61`）。

**新方案设计（保语义、换宿主）**：

- **决策权集中到 Degradation 实例**：它持有 `ladder` + `available` + 按会话隔离的目标状态，是降级的**唯一裁决者**。Warden/Envelope 只负责"发现故障并报告失败上下文"，**不做选级**。
- **故障上下文直传，不经多跳信号**：把现在的 `scope.emit(Signal)` + `settle` + `ctx.degrade_target` + `_sticky_targets` 四跳，收敛为 `Invocation.meta` 里的一个具名故障记录（含 `failed_target: str`，语义同 B2：后端注册名）+ Degradation 实例的 `select(故障记录)`。**信号链删除，但四个坑的语义必须在新结构上逐条复现**。
- **跨 Effect 继承**：B1 的"按会话隔离"要在 Degradation 实例内用 `dict[session_id, 状态]` 保留；不得退化为容器级单值。
- **网关侧不变**：`gateway.py` 的 REFUSE 真拒答、未注册目标 `TargetUnresolved` 不回退（:145-153,187-189）全部保留——这是 R4 红线，不随扩展体系改动。降级 target 如何进入网关调用要重新定死一条 typed 路径（替代 `ctx.degrade_target`），并保证与 Registry 同源。

**改法（执行时按此顺序）**：
1. 先把 `Signal`/`settle`/`sticky_targets` 的三个语义（意图 / 选级 / 跨 Effect 继承）在 Degradation 实例上重新落点，写单测覆盖 B1/B2/R3-6/R3-7 四个历史场景；
2. 再把 Degradation 注册为 Salvage，接 AOP 异常/失败出口；
3. 最后删旧信号链，并保留端到端降级用例（`tests/r3/test_e2e_degrade.py`、R3-E01/E02/E03）作为回归门禁——**这些用例必须在新体系下继续通过，不许改断言放水**。

**涉及代码**：`src/harness/resilience/defenses.py:79-128`（Degradation + select）、`breaker.py:60-67,224-245`、`retry.py:53-54,94-97`、`timeout.py:40-41,58-61`、`src/hooks/v5.py:317,351-357,457-475`、`src/harness/model/gateway.py:145-153,175-198`、`src/aop/container.py`。

### P10 · R7 文档自身缺陷（与新方案无关的独立问题）
