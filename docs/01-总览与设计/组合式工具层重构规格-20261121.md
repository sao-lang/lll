## 1. 重构目标与根因

### 1.1 目标态

**算子是框架核心；R2 取消；R1 不变；挑选层/组合层/工具层不变；对外 API 不变。**

- **核心层 R1（不变）**：Effect 解释器、状态折叠、预算强制、checkpoint、CancellationToken、notify 回调。**一行代码不改**，不认识任何领域。
- **取消 R2**：AOP 五角色容器、LifecycleBus、Registry 不再作为独立模块/框架概念存在。其能力由组合层的算子体系承接（见 §2）。
- **组合层 = 算子核心**：框架的真正核心，用算子把工具层装配成 Program，并构造注入 R1 的 call。
- **工具层 R3-R7 + 用户自定义（不变）**：可挑选可组合，「想要哪个就用哪个，使用上通过组合的形式」。
- **对外 API 不变**：`seq/par/branch/...` 组合式 API + 10 内置架构组合式 API —— 它们都是 §2.3 的 A 类算子，用户无感。

### 1.2 根因（已取证）

1. **组合层是空缺口**：R12 算子/十架构至今是设计态，`src/compose/`/`src/archs/`/`tests/r12/` 不存在。组合层空着，领域复杂度只能下沉内核与 harness。
2. **AOP 把三类东西塞进一条固定链**：调研（`src/aop/protocols.py:49-86`）确认 AOP 混着——A 类一次调用前后插逻辑（可被算子吸收）、B 类跨调用状态机（熔断/限流/幂等/降级，本质是组件）、C 类广播通知（本就该 Lifecycle）。固定角色链是强行凑出来的产物，取消。
3. **retry/budget 没有真实实现**：`x-retry`/`x-budget` 在 src/tests **零消费点**，`src/compose/` 不存在。真正在干活的是 `RetryPolicy.wrap()`（`retry.py:65-92`）和 `BudgetGuard`（`defenses.py:376`）。新方案按真实执行形态建模，不保留空壳算子。

### 1.3 R1 不变的边界（设计的硬约束）

R1 的 `CallFn = (effect, ctx) -> Awaitable[Result]`（`types.py:724-725`），注入点 `Runner(call=...)`（`runner.py:190-212`），调用点 `runner.py:322`。**但 call 只覆盖 `Invoke`**：`Spawn` 在 `_execute` 入口被截走（`runner.py:312-313`），`Suspend`/`Terminate` 在 step 批次层走快路径（`runner.py:491-509`）。

⇒ 后果：call 层的算子（重试/审计/护栏/熔断）**拦不到 Spawn/Suspend/Terminate**。对这三类只能经 `notify` 观察（看不改）。审计/追踪若需覆盖它们，登记为未来 R1 微改可选项（见 D-8）。本规格严守 R1 不变。

## 2. 核心设计：能力与承载形态二维分类（本篇最重要）

### 2.1 第一维：能力（做什么）—— 不变

能力全景图 18 域 169 项（`docs/01-总览与设计/能力域全景.md`）是**需求侧清单**，本次重构**一项不删、一项不改名**。它们回答"Agent 要会什么"。

### 2.2 第二维：承载形态（靠什么实现）—— 七种，这是重构的锚

169 项能力落到实现上只有 7 种承载形态，按 agent 运行周期排列：

| # | 承载形态 | 签名/接口 | 运行期位置 | 代表能力 | 是不是"算子" |
|---|---|---|---|---|---|
| ① | **组合算子** | `Program → Program` | 装配期 | 编排：seq/par/branch/race/loop/fallback/gate/map_state/map_effect/retry(流程级) | ✅ **狭义算子就是这类，框架核心** |
| ② | **有状态守卫** | `check(effect,ctx)→Verdict\|None` + `observe(effect,result,ctx)` | 实例（跨调用存活） | 熔断/限流/舱壁/幂等/降级阶梯/watchdog | ❌ 组件（由③驱动） |
| ③ | **call 装饰器** | `CallFn → CallFn` | 运行期 call 层 | 重试(调用级)/timeout(调用级)/危险路由/注入检测 | ❌ 装饰器；链式组合取代原 AOP 五角色 |
| ④ | **通知观察** | `notify(phase, payload)` 只读 | 旁路 | 链路追踪/审计日志/指标/成本归因 | ❌ R1 既有 notify 回调 |
| ⑤ | **Port 接入** | `Protocol` + Registry | 被 call 调用 | 工具系统/沙箱/LLM/记忆/RAG/Store | ❌ 能力契约 |
| ⑥ | **组件** | 普通类/函数 | 装配或调用期 | 切分/嵌入/重排/改写/规划器/上下文四链 | ❌ 无横切无状态机的算法 |
| ⑦ | **内核机制** | R1 内部 | R1 | 预算/终止/挂起/checkpoint/取消 | ❌ 不进算子层 |

**关键定性**：
- "算子"在本文专指 ① 组合算子（对外 API 的那批）。retry/timeout/熔断/降级/沙箱/工具/追踪**都是能力，不是算子**——它们的"算子"字样只出现在描述承载形态时。
- ② + ③ 取代原 AOP：③ 是无状态 call 装饰器链，② 是有状态守卫实例，③ 在调用前后驱动 ② 的 check/observe。能力不丢，固定角色链消失。
- ④ 就是 R1 现有的 notify 回调。⑤⑥ 本来就该可插拔。

### 2.3 A 类组合算子完整清单（从 169 项能力 + 生命周期反推）

| 算子 | 签名 | 语义 | 覆盖的能力/生命周期 |
|---|---|---|---|
| seq | `seq(a, b)` | a.output 作 b 初始输入 | 各类顺序链路 |
| par | `par([...], join=all)` | 扇出并行 + join 聚合；真并行靠 yield Effect 列表走 R1 解释器（非 EffectBatch 伪 API） | A6/H8/J3 |
| branch | `branch(fn, arms, default?)` | fn(state)→key 选 arm | I1 级联（嵌套 branch） |
| race | `race([...])` | 首个完成胜出，取消其余 | 竞速；依赖 A5 取消传播 |
| map_state | `map_state(lens)` | State 视图变换，纯函数 | F7/E5 |
| retry | `retry(p, *, attempts, backoff)` | **流程级**重放：失败按 program_factory 重建重跑 | 生命周期 T6（流程级；调用级重试归③） |
| fallback | `fallback(p, *, ladders, refuse)` | 按序尝试 arms，某 arm 失败切下一个，全失败走 refuse | B3/C3/H16 降级 |
| loop | `loop(body, *, cond, max_rounds)` | 显式循环（轮次交 Budgets，禁自数） | T2/T6 思考-工具循环、反思轮换 |
| map_effect | `map_effect(fn)` | 改写 Effect payload（脱敏/参数规范化/注入标记） | T0/T2；取代 AOP Refiner |
| gate | `gate(p, policy)` | 可 `yield Suspend(question,options)` 等审批/澄清，resume 后续跑 | T4；call 装饰器不能 yield Effect，挂起类横切只能 A 类 |

共 10 个。级联路由 = 嵌套 branch，不加算子。预算治理不是算子（硬限在 R1 `Budgets`/`fold`，软限是文本提示，用 map_effect 注入 `payload['budget']`）。

**A 类算子统一约束**（R1 不变前提下）：
- 装配期纯变换，`Program → Program`，不改原对象（compile 幂等）；
- **必须是纯函数**：resume 靠 program_factory 重建（`types.py:521-531` 的 Spawn 同构机制），任何运行期状态进 `State.scratch` 的 `x-*` 键，禁止算子实例持有流程进度（否则 resume 丢失）；
- 轮次/跳数交 Budgets（`R12:55-56` 红线），架构 generator 内禁 `for i in range(max)` 自数；
- State 只读（scratch 是 MappingProxyType，`types.py:321-369`），改状态只能 yield Effect 让 fold 写（`runner.py:535` 是唯一写入点）；
- `gate` 的 Suspend 和 `race` 的取消走 R1 快路径/cancel 设施，算子只编排不重实现。

### 2.4 B/C 类：call 装饰器 + 有状态守卫

**③ call 装饰器**（签名是 R1 既有 `CallFn`，`types.py:724-725`）：

```python
def retry(base: CallFn, *, attempts: int, backoff: BackoffSpec) -> CallFn: ...      # 调用级重试
def timeout(base: CallFn, *, seconds: float) -> CallFn: ...                          # 调用级超时(wait_for)
def danger_route(base: CallFn, registry) -> CallFn: ...                             # 按 danger 进沙箱
def injection_guard(base: CallFn, detector) -> CallFn: ...                          # 注入检测
# 组装：call = retry(timeout(danger_route(base_port_call)))
```

- 用**函数组合**表达，无固定角色链、不叫 AOP。
- 只覆盖 `Invoke`（R1 边界，见 §1.3）。

**② 有状态守卫**（统一协议）：

```python
class Guard(Protocol):
    name: str
    async def check(self, effect: Effect, ctx) -> Verdict | None: ...               # 准入；None=放行
    async def observe(self, effect: Effect, result: Result, ctx) -> None: ...       # 后置记账
```

承载：熔断（三态+滑窗+store）、限流（令牌桶）、舱壁（池计数）、幂等（去重表+TTL）、降级阶梯（available 永久剔除+session 隔离）、watchdog（历史滑窗）、killswitch（外部 flag）。

- **由 ③ 的 call 装饰器驱动**：装饰器在调 base 前调 `guard.check`，拿到 Result 后调 `guard.observe`——不需要 AOP 容器。
- 状态存在守卫实例上（沿用 `R3-可靠性.md:58-65` 已确立的语义），注册到组合层装配器。
- **守卫只能持有跨调用的策略状态**（熔断计数等），**不能持有单次流程进度**（那是 A 类 + State.scratch 的职责，见 §2.3 纯函数约束）。

### 2.5 call 注入链

```python
def build_call(ports, decorators, guards) -> CallFn:
    base = lambda effect, ctx: dispatch(ports, effect, ctx)   # 按 effect.port 分派，构造 Result(含 usage)
    call = base
    for deco in decorators: call = deco(call)                 # ③ 装饰器链
    for guard in guards: call = with_guard(call, guard)       # ② check/observe 包裹
    return call
# Runner(call=build_call(...)) —— R1 一行不改
```

`dispatch` 最小职责：签名 `async (effect,ctx)->Result`；按 `effect.port` 取 payload 参数（`gateway.py:215-221`）；构造 `Result.success/failure` 含 `Usage`/`PortError`（`types.py:211-243`）。**不构造 Invocation**（R1 明确不构造，`R1-核心运行时.md:172`）；typed target 消费仅降级场景需要，由 ②降级守卫 + ③装饰器协作完成。

### 2.6 依赖方向（不变量）

```
工具层（R3-R7 + 用户自定义，产出 Program）
    ↓ 装配期
组合层（A 类算子编排 Program + B/C 类构造 call + provides/requires 校验）
    ↓ 注入 call=
核心层 R1（不变，只解释 Program）
```
R1 零依赖上层；组合层是唯一知道"有哪些工具层"的地方；工具层互不直连。
