# 插件封装指南：框架没有的功能怎么加

> 你的问题：项目需要但框架没内置的功能，怎么封装成插件？有没有 API 真正操作内层流程？
> 诚实的答案分三层：**能改 Effect 用 around（真生效）**；**只读/拦截用 guard/observe（真生效）**；**宣称的 8 种 action 里有 4 种是空壳（需知道）**。
> 本文基于 2026-11-17 实测（含刚修复的 3 个 bug），不是照文档抄的。

---

## 一、先说结论：能碰到内层的什么

```
                    ┌─ HookCtx 能看到 ────────────────────────┐
插件收到的 ctx = { effect, state, session_id, event, attempt,
                   budget_left, trace, meta, invoke }
                    └─ invoke 是 R1 注入的 Port 调用函数 ──────┘

插件能改的：
  ✅ ctx.effect       —— 改 payload/kind，真正传给 Port（用 around 包裹 invoke）
  ✅ ctx.meta         —— 任意临时数据（注入的 context 落地这里，但需要有人消费）
  ❌ ctx.state        —— State 是 frozen，改不了（只能读；要改走 Decision.state_patch，但当前未实现）
  ✅ 是否调用 Port    —— guard 短路（deny/abort）可阻止；around 可不调 next 阻止
  ✅ 调用结果         —— around 可包装 Result；fallback 可替换结果
```

**关键**：`ctx.invoke` 是 R1 注进来的"调用真实 Port"的回调。around hook 拿到它，就能**包住真正的 IO**——这是唯一能"操作内层流程"的 API。

---

## 二、8 种 Decision action 的真实生效情况（实测）

| action | 文档宣称 | 代码实际（2026-11-17 实测） | 能用吗 |
|--------|---------|---------------------------|--------|
| `CONTINUE` | 放行 | ✅ 调 Port，正常 | ✅ |
| `DENY` | 拒绝不调用 | ✅ run=error，Port 不调 | ✅ |
| `ABORT` | 终止 | ✅ run=error，Port 不调 | ✅ |
| `FALLBACK` | 兜底值 | ✅ 用 value 作结果，Port 不调 | ✅ |
| `REWRITE` | 改写 payload/context | ⚠️ 只改 ctx.effect/meta，**R1 不用改后的 effect 调 Port** → 对执行无效 | ❌ 别指望 |
| `DEGRADE` | 换目标重跑 | ❌ 空壳，等同 continue（target 没人消费） | ❌ |
| `RETRY` | 重放 Effect | ❌ 空壳，等同 continue（R3 策略未实现） | ❌ |
| `ASK` | 转人工挂起 | ❌ 空壳，等同 continue（HumanPort 未接入） | ❌ |

> 这就是为什么你"感觉没有暴露内层 API"——设计文档承诺了 8 种，真正打通的只有 4 种。
> 我在本次核查中修了 3 个 bug（见第五节），但 `rewrite/degrade/retry/ask` 的**语义实现**属于 R3/R9 未实现模块，不是 bug 是缺口。

## 三、现在就能用的封装方式（三种，按能力排序）

### 方式 1：around hook —— 真正改写传给 Port 的东西（最强大）

```python
from dataclasses import replace
from hooks import HookCtx, HookMode, Decision, HookBus

class ModelRouter:
    """把LLM请求改写：给系统提示词加前缀 + 换模型。"""
    name = "model_router"
    events = ("before_invoke",)
    mode = HookMode.AROUND          # 关键：只有 around 能碰到 invoke
    priority = 10
    requires_ports = ()

    async def __call__(self, ctx: HookCtx) -> Decision:
        # 1. 改写 effect —— 这是真正传给 Port 的对象
        payload = dict(ctx.effect.payload)
        msgs = list(payload.get("messages", []))
        msgs.insert(0, {"role": "system", "content": "你是一个严谨的助手"})
        payload["messages"] = msgs
        payload["model"] = "claude"
        ctx.effect = replace(ctx.effect, payload=payload)

        # 2. 调 next() → 最后进入 ctx.invoke（用改后的 effect 调 Port）
        return await ctx.meta["next"]()

# 装配：bus.on() 是唯一注册入口
bus = HookBus()
bus.on(ModelRouter())
bus.freeze()   # 装配期校验：留名 + 依赖端口齐备
```

**能做什么**：换模型、注入系统提示、改写工具参数、包装 Result（重试/降级的雏形）、记录耗时（在 next() 前后各记一笔）、甚至**不调 next() 直接短路**（fallback）。
**铁律**：around 里改的必须是 `ctx.effect`（invoke 中心读它），不是原始 effect。

### 方式 2：guard hook —— 拦截/判决（不调用 Port）

```python
class PIIGuard:
    """敏感信息护栏：命中就拒绝调用。"""
    name = "pii_guard"
    events = ("before_invoke",)
    mode = HookMode.GUARD          # 串行、按 priority、首个非 continue 短路
    priority = 5
    requires_ports = ()

    async def __call__(self, ctx: HookCtx) -> Decision:
        text = str(ctx.effect.payload.get("messages", ""))
        if "身份证" in text:
            return Decision.deny("检测到敏感信息")
        return Decision.continue_()
```

### 方式 3：observe hook —— 只读审计（异常隔离）

```python
class AuditLog:
    name = "audit"
    events = ("before_invoke", "after_invoke")
    mode = HookMode.OBSERVE        # 并行、异常隔离、返回忽略
    priority = 1
    requires_ports = ("audit",)    # freeze 时校验 port 已注册

    async def __call__(self, ctx: HookCtx) -> Decision:
        ctx.trace.append(f"{ctx.event}:{ctx.effect.kind.value}")
        return Decision.continue_()
```

### 装配到 Runner（唯一的拼接方式）

```python
runner = Runner(
    dispatch=lambda effect, ctx: bus.emit(ctx.event or "before_invoke", ctx),
    call=my_llm_port,                    # 你注入的真实/自定义 Port
    ctx_factory=bus.ctx_factory(),       # R1 用工厂产出 HookCtx
)
```

## 四、如果功能复杂到 hook 装不下怎么办

Hook 适合**横切行为**（日志/护栏/改写/包裹）。如果你要的是**全新的执行流程**（比如一个新的多 Agent 架构、自定义规划器），正路是写 **Program**——因为框架铁律是"架构即 Program"：

```python
def my_custom_flow(state: AgentState):
    """自定义流程就是一个 generator，yield Effect 声明要做什么。"""
    plan = yield Effect(EffectKind.LLM, {"messages": [...]})   # 声明，不执行
    result = yield [Effect(EffectKind.TOOL, {"call": step}) for step in plan["steps"]]
    yield Effect(EffectKind.END, {"output": summarize(result)})
```

Program 里只能 yield 6 种内置 Effect（LLM/TOOL/CHILD/SKILL/WAIT_HUMAN/END）。如果确实需要**新的外部能力**（比如向量库、浏览器），走 **Port 替换**——实现对应 Protocol，注册进 Registry：

```python
class MyVectorStore:
    name = "my-vector-store"
    async def upsert(self, chunks): ...
    async def search(self, vec, top_k, filters): ...
registry.register("rag", MyVectorStore())   # 协议替换，上层零改动
```

三条路的选择：
- **横切行为**（所有请求都要做）→ Hook（bus.on）
- **新执行流程** → Program（yield Effect）
- **新外部能力** → Port（实现 Protocol + registry.register）

## 五、本次核查发现并修复的 3 个真实 bug

你的提问直接暴露了 R1↔R2 集成的严重问题，我实测后修复：

1. **所有插件被误判 abort**：R1 用 `getattr(outcome, "abort", False)` 判断，而 `Decision.abort` 是类方法（truthy）→ 任何 hook 返回 Decision 都变 `chain aborted`。改为按 `action` 字段判断，且排除 callable。
2. **Port 被调用两次**：around 中心的 invoke 调了一次，R1 拿到 continue 后又用原始 effect 调了一次 → 插件改写失效 + 工具副作用执行两次（灾难性）。改为 core 把 invoke 的 Result 装进 `Decision.value`，R1 直接采用不再重复调。
3. **裁决字段不一致**：R1 读 `outcome.data`，Decision 实际字段是 `value` → 永远读不到。统一为 `value`。

修复都有回归测试（`tests/r2/test_extensibility.py` + `tests/r1/test_dispatch_verdict.py`），全量 66 测试通过。

## 六、想让 4 种空壳 action 真正可用

`rewrite`（对执行生效）/ `degrade` / `retry` / `ask` 需要对应模块落地，不在 R1/R2 范围：
- `retry` → R3 可靠性（退避策略 + 幂等键）
- `degrade` → R4 模型降级链
- `ask` → R9 安全与 HITL（HumanPort 挂起恢复）
- `rewrite` 对执行生效 → 需要 R1 `_execute` 用 `ctx.effect` 而非参数 `effect` 调 Port（留待契约评审后改，因为它触碰 G5 锁定的行为）

在那之前，**用 around hook 手搓**都能实现同等效果（重试就是循环调 next()、降级就是换 effect.model、人工就是在 hook 里挂起）。
