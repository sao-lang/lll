# 插件封装指南：框架没有的功能怎么加（v5）

> 你的问题：项目需要但框架没内置的功能，怎么封装成插件？v5 有没有 API 真正操作内层流程？
> 答案：**有，但只有一个入口**——插件实现 `apply(host)`，用 `host.hook(name).tap(name, fn)` 订阅宿主定义的扩展点；通过 `RequestScope` 发信号 / 写降级目标，跨调用状态由插件实例自身持有（插件注册一次、长期存活，天然跨调用），没有独立 Policy 层。
> 本文对应 v5.1 架构（`src/hooks/v5.py` / `.workbuddy/specs/ARCH-v5.md`）；旧一代插件 API（mode 类属性、全局总线注册、`scope.meta` 裸键回调参数）全部作废，不做兼容。v5.1 起请求期输入（effect）走回调签名直送、装配期配置走构造注入。

---

## 一、先说结论：一个入口、5 种原语、6 个扩展点

```
插件唯一扩展点：Plugin.apply(host)
    └─ host.hook(name).tap(self.name, self.fn)     # 订阅宿主定义的扩展点
         └─ 6 个扩展点由宿主定义时选定 HookKind（effect 直送回调签名）：
              before_invoke  → BAIL       fn(scope, effect)        拦截 / 短路
              transform      → WATERFALL  fn(value, effect)        链式改写
              around_invoke  → AROUND     fn(next, scope, effect)  包裹真实 IO
              after_invoke   → PARALLEL   fn(scope, effect)        成功观察
              invoke_error   → PARALLEL   fn(scope, effect)        失败观察（scope 带 last_result）
              settle         → BAIL       fn(scope, effect)        降级裁决
```

**v5 里能碰到的内层**：

- `scope`（`RequestScope`）：每次调用新建的 typed 协作容器（**没有 meta 字段**）——`scope.emit(Signal(...))` 发请求内信号，`scope.target` 写降级目标（Host 刷新到 `ctx.degrade_target` 供 R4 读），`scope.last_result` 观察只读，`scope.trace` 记轨迹，`scope.releases` 登记资源释放回调（Host 每轮结束逆序执行），`scope.value` 传值。
- `effect`：请求期输入参数，由 `Hook.call(scope, effect, ...)` 直送每个 tap——BAIL/LOOP/PARALLEL 收 `fn(scope, effect)`、WATERFALL 收 `fn(value, effect)`、AROUND 收 `fn(next, scope, effect)`。它不进任何共享容器，避免被先执行的插件篡改。
- `next_fn`：AROUND 插件收到的下一层回调，最内层 `core` 由 R1 注入的 `call` 指回真实 Port（`ModelGateway.as_call`）。调 `next_fn()` 才执行 IO，不调就短路。
- 跨调用状态由**插件实例自身**持有：熔断三态机、降级 ladder+available 直接放在插件实例上（注册一次、长期存活，天然跨调用）；装配期配置由构造参数注入，不再塞进临时容器，也没有独立 Policy 层。

**不能碰的**：`State` 是 frozen（要改走 `Decision.state_patch`，由 R1 消费）；插件**不声明**调用语义、优先级或订阅清单——这些由宿主在 `define()` 扩展点时选定，顺序由 tap 序决定。

---

## 二、5 种 HookKind 的调用语义（宿主定义时选，插件不声明）

| kind | tap 回调签名 | 语义 | 典型扩展点 |
|------|-------------|------|-----------|
| `Bail` | `fn(scope, effect)` | 按 tap 序执行，首个非 `None` / 非 continue 的 Decision 即停 | `before_invoke`、`settle` |
| `Waterfall` | `fn(value, effect)` | 上次返回值作下次首参，链式改写 | `transform` |
| `Loop` | `fn(scope, effect)` | 任一 tap 返回非 `None` 则重跑整链（带上限，防死循环） | 自定义 |
| `Parallel` | `fn(scope, effect)` | 全执行、异常隔离、返回 `None` | `after_invoke`、`invoke_error` |
| `Around` | `fn(next, scope, effect)` | tap 收到 `next` 回调，包裹中心调用（洋葱模型） | `around_invoke` |

## 三、三种典型插件（v5 写法）

### 方式 1：AROUND 插件 —— 包裹 / 短路真实调用（最强大）

```python
from hooks.v5 import Plugin, Signal

class ModelRouter(Plugin):
    """包裹真实调用：前后处理 + 命中规则可短路。"""
    name = "model_router"

    def apply(self, host):
        # 一个插件可注册多个扩展点；这里订阅 around_invoke（AROUND 语义）
        host.hook("around_invoke").tap(self.name, self.fn)

    async def fn(self, next_fn, scope, effect):
        # AROUND 签名 fn(next, scope, effect)：next_fn 是下一层回调，effect 是当前请求输入（直送）
        # 调 next_fn() 才进入真实 IO（中心由 R1 注入的 call 提供）
        try:
            result = await next_fn()
        except Exception as exc:
            # 故障用信号告诉 settle 裁决降级，不在这里替别人改目标
            scope.emit(Signal("degrade", f"invoke_error: {exc}"))
            raise
        # 在 next_fn() 前后各记一笔即可统计耗时；也可在此包装 Result
        return result
```

**能做什么**：在 `next_fn()` 前后算耗时；包装 Result；按规则**不调 `next_fn()` 直接短路**（等价兜底 / 拒绝）；检测到故障就 `scope.emit(Signal("degrade", reason))`，让 `settle` 统一裁决降级。
**改写载荷**：要真正改写请求内容（预算 / 上下文），请用 `transform`（WATERFALL）——它的 tap 是 `fn(value, effect) -> value` 链式改写（effect 直送），而不是在 around 里改入参，更不要往共享容器里塞参数。

### 方式 2：BAIL 插件（守卫）—— 拦截，不调用 Port

```python
from hooks.v5 import Plugin, Decision

class PIIGuard(Plugin):
    """敏感信息护栏：命中就拒绝调用。"""
    name = "pii_guard"

    def apply(self, host):
        # before_invoke 是 BAIL：首个非 continue 的 Decision 即短路，Port 不被调用
        host.hook("before_invoke").tap(self.name, self.fn)

    async def fn(self, scope, effect):
        # BAIL 签名 fn(scope, effect)：请求输入从直送的 effect 读，
        # 绝不从共享容器取（没有 scope.meta，避免被前一个插件篡改入参）
        text = " ".join(str(m.get("content", "")) for m in effect.payload.get("messages", []))
        if "身份证" in text:
            return Decision.deny("检测到敏感信息")
        return Decision.continue_()
```

### 方式 3：PARALLEL 插件（观察）—— 只读审计，异常隔离

```python
from hooks.v5 import Plugin

class AuditLog(Plugin):
    name = "audit"

    def apply(self, host):
        host.hook("after_invoke").tap(self.name, self.fn)   # 成功观察
        host.hook("invoke_error").tap(self.name, self.fn)   # 失败观察（scope 带 last_result）

    async def fn(self, scope, effect):
        # PARALLEL 签名 fn(scope, effect)：tap 抛异常被框架隔离，不影响主流程
        # 结果写在 RequestScope 的 typed 字段，无需 meta 容器
        scope.trace.append(str(scope.last_result))
```

### 跨调用状态：插件实例自身持有

熔断三态机、降级阶梯这类**跨请求状态**直接放在插件实例上——插件注册一次、长期存活，天然跨调用；不需要独立 Policy 层，也不塞进临时容器：

```python
from hooks.v5 import Decision, Signal

class Degradation:
    """降级插件：状态（ladder + available）直接在本实例上。"""
    name = "degradation"

    def __init__(self, ladder):
        self.ladder = ladder                      # target 名与网关注册名约定一致
        self.available = set(ladder)

    def select(self, signals):
        available = set(self.available)
        for sig in signals:
            if sig.failed_target:
                available.discard(sig.failed_target)
        return next((t for t in self.ladder if t in available), "refuse")

    def apply(self, host):
        host.hook("settle").tap(self.name, self.settle)

    async def settle(self, scope, effect):   # settle 是 BAIL，签名 fn(scope, effect)
        sigs = [s for s in scope.signals if s.kind == "degrade"]
        if not sigs:
            return None
        return Decision.degrade(self.select(sigs))
```

### 装配示例（唯一的拼接方式）

```python
from hooks.v5 import Host

host = Host()
host.plugin(ModelRouter())          # 内部调 plugin.apply(host)
host.plugin(PIIGuard())
host.plugin(AuditLog())
host.plugin(Degradation(["llm_backup", "refuse"]))  # 状态随实例注册，长期存活
host.freeze()                       # 装配期校验：留名 + 依赖端口齐备

# R1 注入点：dispatch / call 签名不变
runner = Runner(
    dispatch=host.dispatch,
    call=host.call(my_llm_port),
)
```

## 四、如果功能复杂到插件装不下怎么办

插件适合**横切行为**（日志 / 护栏 / 改写 / 包裹）。如果你要的是**全新的执行流程**（比如一个新的多 Agent 架构、自定义规划器），正路是写 **Program**——框架铁律是"架构即 Program"：

```python
def my_custom_flow(state: AgentState):
    """自定义流程就是一个 generator，yield Effect 声明要做什么。"""
    plan = yield Effect(EffectKind.LLM, {"messages": [...]})   # 声明，不执行
    result = yield [Effect(EffectKind.TOOL, {"call": step}) for step in plan["steps"]]
    yield Effect(EffectKind.END, {"output": summarize(result)})
```

Program 里只能 yield 6 种内置 Effect（LLM/TOOL/CHILD/SKILL/WAIT_HUMAN/END）。如果确实需要**新的外部能力**（比如向量库、浏览器），走 **Port 替换**——实现对应 Protocol，注册进 Registry：

```python
class MyVectorStore:
    name = "my-vector-store"
    async def upsert(self, chunks): ...
    async def search(self, vec, top_k, filters): ...
registry.register("rag", MyVectorStore())   # 协议替换，上层零改动
```

三条路的选择：

- **横切行为**（所有请求都要做）→ Plugin（`host.plugin(...)`，内部 `apply(host)` 订阅扩展点）
- **新执行流程** → Program（yield Effect）
- **新外部能力** → Port（实现 Protocol + `registry.register`）

## 五、怎么写一个好插件（领域指导）

1. **职责单一**：一个插件只做一件事；要订阅多个扩展点可以，但别把护栏、改写、审计混在一个类里。
2. **留名**：`name` 必填且稳定，trace 与诊断全靠它；`tap` 时传的插件名要和它一致。
3. **显式声明依赖**：要用哪个 Port 就从 `host` 显式取；跨调用状态由插件实例自身持有、随 `host.plugin(...)` 注册，`host.freeze()` 会在装配期校验留名与依赖齐备。
4. **异常隔离**：PARALLEL 观察类 tap 的异常由框架吞掉；写 AROUND 逻辑时注意别把主流程异常吞掉——该抛出就抛出，降级意图用 Signal 表达。
5. **用信号而非隐式耦合**：故障用 `scope.emit(Signal(...))`，由 `settle` 统一裁决降级目标；不要直接改别人的 state 或偷偷改全局。
6. **跨调用状态在插件实例自身，装配配置走构造注入**：熔断计数、降级阶梯等跨请求状态直接放插件实例（注册一次、长期存活）；熔断维度/失败目标/舱壁池名/watchdog kind 等判定参数由构造参数注入。请求期输入只有直送的 `effect`——`RequestScope` 没有 `meta` 字段，不要往公共容器塞参数（会被任意插件篡改），也没有独立 Policy 层。
7. **不声明调用语义**：mode / 优先级 / 订阅清单由宿主在定义扩展点时选定，插件只管 `apply(host)` 里 tap 哪些扩展点；执行顺序就是 tap 顺序。
8. **不改运行时内核**：Effect / State / Result 是框架的确定性契约，插件只通过扩展点与 Decision / Signal 交互。
