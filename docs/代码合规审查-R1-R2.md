## 逐项问题与处理

### 规则 1：完整注释（34 处）

- `protocols.py`：13 个 Port 协议的 28 个方法全是 `...` 无 docstring → 每个补一句话（契约即文档）。
- `bus.py`：`__init__`、`core`、`layer`、`nxt` 4 个嵌套/构造函数缺 → 补。
- `hooks/types.py`：`Hook.__call__`、`Capability.install`、`Registry.__init__` 缺 → 补。
- `interpreter.py`：`Interpreter.send`、`runner.py`：`InMemoryEventStore.__init__`、`types.py`：`__repr__`/`__getattr__` 缺 → 补。

**处理**：全部补齐。协议方法的 docstring 尤其重要——它们是"可插拔契约"的文档本身。

### 规则 2：完整类型（符合）

无 `typing.List/Dict/Optional/Union` 泛型滥用，所有函数签名完整。此条通过（无需修改）。

### 规则 3：明确字段不能写成动态键（重点）

| 位置 | 问题 | 处理 |
|------|------|------|
| `AgentState.with_(**changes)` | 托管字段（output/last_*）是明确字段，却走 `**dict` 动态拼装 | 保留 `with_` 作为通用入口（用户键确实动态），但内部改为显式构造；新增类型化的 `with_fields()` 供明确字段使用 |
| `AgentState.set(key, value)` | 明确托管字段调用 `with_(**{key:value})` | 改为 if 分支显式传参 |
| `Effect.with_payload(**extra)` | EffectPayload 已知键，动态 `**extra` | 改为接受 `EffectPayload` 类型化 patch（仍向后兼容 `**kwargs`） |
| `fold.py:120` `with_(**managed)` | 托管字段用 dict 拼 | 改为显式关键字参数构造 |
| `types.py:493` `**managed` | restore_state 同上 | 同上 |
| `interpreter.py:38` `{**payload, "call": call}` | 这是 payload 合并（x-* 动态扩展），属允许场景 | 加注释说明为何动态 |

**原则**：**用户自定义键（scratch/x-*）允许动态；框架托管字段（编译期可枚举）必须显式。**

### 规则 4：减少 Any（12 处）

- `hooks/types.py`：
  - `budget_left: Any` → `Budgets | None`（明确类型）
  - `invoke: Callable[..., Awaitable[Any]]` → `Awaitable[Result]`（R1 注入的真实返回）
  - `Capability.install(bus: Any)` → 用 `HookBus` 协议前向引用（`TYPE_CHECKING`）
- `dto.py`：8 处 `Any` 改为 `DynamicValue`（从 runtime 导入具名别名），并加注释说明为何动态（工具参数/JSON Schema/meta 形态由外部 port 决定）。
- `runtime/types.py`：`Any` 仅保留在 `DynamicValue` 别名定义处（集中动态边界），符合规则精神。

### 规则 5：新语法（1 处）

- `DoneSentinel: TypeAlias = _Done` → `type DoneSentinel = _Done`（PEP 695，3.12+），移除 `TypeAlias` 导入。

---

## 不修改项（说明理由）

- `scratch: Mapping[str, DynamicValue]` / `meta: dict[str, DynamicValue]` / `EffectPayload` 的 `total=False`：这些键由用户或外部 port 决定，编译期不可枚举，属规则 3 明确允许的"动态键"场景，且在类型别名处已集中说明。
- `DynamicValue = Any` 本身：这是规则的"动态边界集中点"，保留（规则 4 要求的是减少散落 Any，不是消灭这一个别名）。
