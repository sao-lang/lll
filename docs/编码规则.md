# 编码规则（AgentKit 全项目强制）

> 适用：`src/` 全部代码。配套：[《代码阅读指南-R1-R2》](./代码阅读指南-R1-R2.md)、[《门禁体系》](./03-流程与规范/门禁体系.md)。
> 基线：Python **≥3.12**（当前环境 3.13.14），mypy `--strict` + pyright 双检查必须 0 error。
> 每条规则给**反例 → 正例**。违者 G1 门禁不绿。

---

## 规则 1：完整注释——模块、类、公共方法都要 docstring

**要求**：
- 模块顶部 docstring：说明职责 + 关键纪律 + 指向设计文档。
- 每个 public 类、`__init__`、public 方法、模块级函数：一行 docstring 说"做什么"，复杂逻辑补"为什么"。
- 非显然的分支/算法/绕坑：行内注释说明**原因**（不是复述代码）。
- 私有 helper 也要一句话 docstring（便于快速阅读）。

```python
# ❌ 反例：无注释
def consume(self, **d):
    return replace(self, used=self.used + d)

# ✅ 正例
def consume(self, *, turns: int = 0, cost_usd: float = 0.0) -> Budgets:
    """按维度增量生成新 Budgets（成本 round 到 10 位避免浮点累积误差）。"""
    ...
```

**例外**：`...` 协议方法体、纯数据类字段、明显的 getter 可不重复注释。

## 规则 2：完整类型——所有签名和字段显式标注

**要求**：
- 函数/方法：参数 + 返回值全部标注，包括 `self` 之外的每个参数和 `-> None`。
- 类字段：全部带类型注解（dataclass 靠字段注解，普通类在 `__init__` 标注）。
- 泛型容器带元素类型：`list[str]`、`dict[str, int]`，禁止裸 `list`/`dict`。
- 允许 `Callable`/`Awaitable` 但参数与返回要写全：`Callable[[Effect], Awaitable[Result]]`。
- `Protocol` 方法同样要标注（签名即契约）。

```python
# ❌ 反例：缺返回类型、裸容器
def fold(state, effects, results):
    msgs = []

# ✅ 正例
def fold(state: AgentState, effects: Sequence[Effect], results: Sequence[Result]) -> AgentState:
    msgs: list[Message] = []
```

## 规则 3：明确字段不能写成动态键

这是最重要的一条。当一个对象的字段是**编译期可枚举的**，必须用 dataclass / TypedDict / NamedTuple 显式声明，禁止用 `dict[str, Any]` 或 `**kwargs` 拼装。

**判定标准**：如果写代码时能列出所有合法键 → 就是"明确字段"，必须静态声明。

```python
# ❌ 反例：明确字段用动态键
decision = {"action": "deny", "reason": "blocked", "retry": None}   # 消费者靠猜键名
state.set("last_skill", value)   # last_skill 是明确字段，应走 with_(last_skill=...)

# ✅ 正例：dataclass / TypedDict 显式声明
@dataclass(frozen=True)
class Decision:
    action: DecisionAction = DecisionAction.CONTINUE
    reason: str = ""
    retry: RetrySpec | None = None

state.with_(last_skill=value)    # 托管字段用显式关键字参数
```

**允许动态键的场景**（必须在注释中说明为何动态）：
- 用户自定义命名空间：`scratch: Mapping[str, DynamicValue]`（键由用户决定，编译期不可知）。
- port 负载：`Effect.payload` 的 `x-*` 扩展键（跨 port 形态未知），但**已知键仍要在 TypedDict 里声明**（如 `EffectPayload`）。
- 元数据透传：`meta: dict[str, DynamicValue]`。

## 规则 4：尽量减少 Any——用具名别名集中"动态边界"

**要求**：
- 禁止裸 `Any` 散落。动态值统一用 `DynamicValue`（`src/runtime/types.py` 里 `type DynamicValue = Any`），并在 docstring 说明"为何动态"。
- 能用 `Protocol` 表达的结构，不用 `Any`（如 `ctx_factory` 返回 `Callable[[Effect, Session], RuntimeCtxLike]` 而非 `DynamicValue`）。
- 能用联合类型表达的，不用 Any（如 `budget_left: Budgets | None`，不是 `Any`）。
- `getattr/setattr` 动态访问后要 `cast` 到具体类型，不要让它污染推断。
- 每个残留的 `DynamicValue`/`Any` 都要能回答："这个值的形态是否真的由外部 port 决定？"

```python
# ❌ 反例
def bind(ctx: Any) -> Any: ...
budget_left: Any

# ✅ 正例
def bind(ctx: RuntimeCtxLike) -> RuntimeCtxLike: ...
budget_left: Budgets | None
```

## 规则 5：使用最新稳定 Python 语法（≥3.12）

**要求且已采用**：
- `type X = ...` 声明类型别名（PEP 695，替代 `X = Any` 的旧写法）。
- `X | Y` 联合类型（替代 `Optional[X]`/`Union[X, Y]`）。
- 内置泛型 `list[T]` / `dict[K, V]` / `tuple[T, ...]`（替代 `typing.List` 等）。
- `from __future__ import annotations` 每个模块首行（延迟求值，支持前向引用）。
- `@dataclass(frozen=True)` 表达不可变值对象；`slots=True` 用于高频小对象。
- `dataclass_transform` / PEP 695 泛型 `class Foo[T]:` 在需要泛型类时使用。

**禁止**：
- `typing.List`/`Dict`/`Optional`/`Union`（新代码一律用新语法）。
- 字符串前向引用能避免就避免（有了 `from __future__ import annotations` 和 PEP 695）。
- 老式 `%` 格式化、`f-string` 之外的拼接。

```python
# ❌ 反例（旧语法）
from typing import List, Optional, Union
def f(x: Optional[Union[int, str]]) -> List[str]: ...
MyType = Any

# ✅ 正例
def f(x: int | str | None) -> list[str]: ...
type MyType = Any
```

## 规则 6：模块内闭环纪律（沿用框架铁律）

- L0 内核不 import 任何 IO SDK（httpx/pydantic）。
- Program 内无时间/随机/网络调用（AST 扫描）。
- 异常不抛穿，折叠为 `Result.failure()` / `Decision`。
- 一切可插拔物带 `name`，装配期校验。
