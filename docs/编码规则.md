# 编码规则（AgentKit 全项目强制）

> **先读精简通用版**：[《通用编码规则》](./通用编码规则.md)（6 条约束 + 强制机器检查，AI 照做即可）。
> 本文是项目内详版：含稳定规则号（被代码注释与 AST 门禁交叉引用）、分层红线与 R1~R5 落地示例。
> **魔法字符串治本手段**：改完代码必跑 `python tools/magic_string_check.py <文件>`，输出为空才算完成——
> 规则 5 的文字约束管不住写码时的顺手裸串，机器检查才行。
>
> 适用：`src/` 全部代码。配套：[《代码阅读指南-R1-R2》](./代码阅读指南-R1-R2.md)、[《门禁体系》](./03-流程与规范/门禁体系.md)。
> 基线：Python **≥3.12**（当前环境 3.13.14），mypy `--strict` + pyright 双检查必须 0 error。
> 每条规则给**反例 → 正例**。违者 G1 门禁不绿。
> 规则按主题分五组编排：**类型与语法 → 数据建模与动态边界 → 注释与可读性 → 架构与依赖纪律 → 工程实践**。规则 11（设计承诺反向闭包核对）属第五组工程实践，是防"假完成"的强制流程。
> **规则号是稳定引用 ID**：`src/` 代码注释、设计文档与 AST 门禁均以「规则 N」交叉引用，请勿随意改动。

## 一、类型与语法（表达力地基）

### 规则 1：完整类型——所有签名和字段显式标注

**要求**：
- 函数/方法：参数 + 返回值全部标注，包括 `self` 之外的每个参数和 `-> None`。
- 类字段：全部带类型注解（dataclass 靠字段注解，普通类在 `__init__` 标注）。
- 泛型容器带元素类型：`list[str]`、`dict[str, int]`，禁止裸 `list`/`dict`。
- 允许 `Callable`/`Awaitable` 但参数与返回要写全：`Callable[[Effect], Awaitable[Result]]`。
- `Protocol` 方法同样要标注（签名即契约）。

```python
# ❌ 反例：缺返回类型、裸容器
def fold(state, effects, results):
    msgs = []

# ✅ 正例
def fold(state: AgentState, effects: Sequence[Effect], results: Sequence[Result]) -> AgentState:
    msgs: list[Message] = []
```

### 规则 2：使用最新稳定 Python 语法（≥3.12）

**要求且已采用**：
- `type X = ...` 声明类型别名（PEP 695，替代 `X = Any` 的旧写法）。
- `X | Y` 联合类型（替代 `Optional[X]`/`Union[X, Y]`）。
- 内置泛型 `list[T]` / `dict[K, V]` / `tuple[T, ...]`（替代 `typing.List` 等）。
- `from __future__ import annotations` 每个模块首行（延迟求值，支持前向引用）。
- `@dataclass(frozen=True)` 表达不可变值对象；`slots=True` 用于高频小对象。
- `dataclass_transform` / PEP 695 泛型 `class Foo[T]:` 在需要泛型类时使用。

**禁止**：
- `typing.List`/`Dict`/`Optional`/`Union`（新代码一律用新语法）。
- 字符串前向引用能避免就避免（有了 `from __future__ import annotations` 和 PEP 695）。
- 老式 `%` 格式化、`f-string` 之外的拼接。

```python
# ❌ 反例（旧语法）
from typing import List, Optional, Union
def f(x: Optional[Union[int, str]]) -> List[str]: ...
MyType = Any

# ✅ 正例
def f(x: int | str | None) -> list[str]: ...
type MyType = Any
```

### 规则 3：尽量减少 Any——用具名别名集中"动态边界"

**要求**：
- 禁止裸 `Any` 散落。动态值统一用 `DynamicValue`（`src/runtime/types.py` 里 `type DynamicValue = Any`），并在 docstring 说明"为何动态"。
- 如果前面声明了一个变量，类型是Any，后面通过这个变量设置某个字段或者获取某个字段，那么这个变量应该声明成一个具体的类型，并且每个字段要标注是什么意思
- 能用 `Protocol` 表达的结构，不用 `Any`（如 `ctx_factory` 返回 `Callable[[Effect, Session], RuntimeCtxLike]` 而非 `DynamicValue`）。
- 能用联合类型表达的，不用 Any（如 `budget_left: Budgets | None`，不是 `Any`）。
- `getattr/setattr` 动态访问后要 `cast` 到具体类型，不要让它污染推断。
- 每个残留的 `DynamicValue`/`Any` 都要能回答："这个值的形态是否真的由外部 port 决定？"

```python
# ❌ 反例
def bind(ctx: Any) -> Any: ...
budget_left: Any

# ✅ 正例
def bind(ctx: RuntimeCtxLike) -> RuntimeCtxLike: ...
budget_left: Budgets | None
```

## 二、数据建模与动态边界（把动态收敛为静态）

### 规则 4：明确字段不能写成动态键

这是最重要的一条。当一个对象的字段是**编译期可枚举的**，必须用 dataclass / TypedDict / NamedTuple 显式声明，禁止用 `dict[str, Any]` 或 `**kwargs` 拼装。

**判定标准**：如果写代码时能列出所有合法键 → 就是"明确字段"，必须静态声明。

```python
# ❌ 反例：明确字段用动态键
decision = {"action": "deny", "reason": "blocked", "retry": None}   # 消费者靠猜键名
state.set("last_skill", value)   # last_skill 是明确字段，应走 with_(last_skill=...)

# ✅ 正例：dataclass / TypedDict 显式声明
@dataclass(frozen=True)
class Decision:
    action: DecisionAction = DecisionAction.CONTINUE
    reason: str = ""
    retry: RetrySpec | None = None

state.with_(last_skill=value)    # 托管字段用显式关键字参数
```

**允许动态键的场景**（必须在注释中说明为何动态）：
- 用户自定义命名空间：`scratch: Mapping[str, DynamicValue]`（键由用户决定，编译期不可知）。
- port 负载：`Effect.payload` 的 `x-*` 扩展键（跨 port 形态未知），但**已知键仍要在 TypedDict 里声明**（如 `EffectPayload`）。
- 元数据透传：`meta: dict[str, DynamicValue]`。

### 规则 5：有限取值集合用枚举，禁止魔法字符串

**要求**：
- 状态、动作、错误码、模式等**有限取值集合**必须用 `Enum`（需与外部字符串协议互通时用 `str, Enum`），禁止裸字符串直接比较或拼装。
- 跨层对齐但需保持本层独立定义时（如 R1 内核要识别 R2 的裁决动作，却不能 import R2），在本层定义**下划线开头的私有枚举**，值与上层协议对齐——既消解魔法串，又不破坏分层红线。
- 未知 / 未识别值必须**显式回退到默认成员**，保持原有 fall-through 语义，不得抛异常或静默改写行为。

```python
# ❌ 反例：魔法串散落，未知值行为不明
if action_name in ("abort", "deny"): ...
if status == "running": ...

# ✅ 正例：私有 str 枚举，值与上层对齐但不 import 上层
class _VerdictAction(str, Enum):
    CONTINUE = "continue"; ABORT = "abort"
    DENY = "deny"; FALLBACK = "fallback"
action = _VERDICT_BY_NAME.get(raw, _VerdictAction.CONTINUE)  # 未知值显式回退
if verdict.action in (_VerdictAction.ABORT, _VerdictAction.DENY): ...
```

### 规则 6：动态边界只留一处，下游只用具名视图

**要求**：
- 对鸭子对象 / 外部 port 返回值的动态字段读取（`getattr` / `field`），只允许收敛到**一个** `_coerce_*` 归一化函数里，并在 docstring 说明"为何动态"。
- 该函数返回 `@dataclass(frozen=True, slots=True)` 具名视图，字段全部带类型；调用方只做属性访问 + 枚举比较，禁止再次散落 `getattr`。这是规则 3"动态边界具名化"的落地形态。
- `getattr` 若用于装配期对**鸭子插件**的容错（插件可能不是协议子类），须在注释写明理由，可保留在边界处。

```python
# ❌ 反例：同一动态对象在 8 处 getattr，Any 到处污染
action = getattr(outcome, "action", None)
reason = getattr(outcome, "reason", "")
value = getattr(outcome, "value", None)

# ✅ 正例：一次归一化 → 具名视图 → 下游纯属性访问
def _coerce_verdict(outcome: DynamicValue) -> _Verdict:
    """唯一的动态读取边界：鸭子判决形态由上层决定。"""
    ...
    return _Verdict(action=action, reason=reason, value=value)

settled = _settle(_coerce_verdict(outcome))   # _settle 内无 getattr
```

## 三、注释与可读性

### 规则 7：完整注释——模块、类、公共方法都要 docstring

**要求**：
- 模块顶部 docstring：说明职责 + 关键纪律 + 指向设计文档。
- 每个 public 类、`__init__`、public 方法、模块级函数：一行 docstring 说"做什么"，复杂逻辑补"为什么"。
- 非显然的分支/算法/绕坑：行内注释说明**原因**（不是复述代码）。
- 每个字段、多分支（嵌套、多if、多if else）、循环语句都要加注释
- 函数、方法的参数和返回值加注释
- 重要变量加注释
- 私有 helper 也要一句话 docstring（便于快速阅读）。

```python
# ❌ 反例：无注释
def consume(self, **d):
    return replace(self, used=self.used + d)

# ✅ 正例
def consume(self, *, turns: int = 0, cost_usd: float = 0.0) -> Budgets:
    """按维度增量生成新 Budgets（成本 round 到 10 位避免浮点累积误差）。"""
    ...
```

**例外**：`...` 协议方法体、纯数据类字段、明显的 getter 可不重复注释。

## 四、架构与依赖纪律

### 规则 8：模块内闭环纪律（沿用框架铁律）

**要求**：
- L0 内核不 import 任何 IO SDK（httpx/pydantic）。
- Program 内无时间/随机/网络调用（AST 扫描）。
- 异常不抛穿，折叠为 `Result.failure()` / `Decision`。
- 一切可插拔物带 `name`，装配期校验。

```python
# ❌ 反例：内核模块直接依赖 IO SDK
# src/runtime/state.py
import httpx  # L0 内核禁止

# ✅ 正例：IO 只出现在 port 适配器，内核只依赖协议
# src/ports/adapters/llm.py
class OpenAICompatLLM(LLMPort): ...
# src/runtime/state.py 只 from ports import LLMPort
```

### 规则 9：可用户自定义实现的协议，框架必须内置默认实现

凡允许用户自定义注入的协议（Port / Hook / Store 等），框架必须同时提供一个可直接使用的内置默认实现，避免"协议公开了但开箱不能用"。

**要求**：
- 协议定义与默认实现成对出现：协议在 `ports/`，默认实现在 `ports/adapters/`。
- 默认实现是协议的最小可用实现，不引入必需的用户配置（如 `LLMPort` 内置 `OpenAICompatLLM`）。
- 用户自定义实现通过依赖注入覆盖默认，装配期按 `name` 校验（呼应规则 8）。
- 新增协议若暂不提供默认实现，须在设计文档标注缺口与补齐模块，不得以"用户自己实现"敷衍。

```python
# ❌ 反例：协议公开但无默认，装配期报错只能靠用户自己写
class LLMPort(Protocol):
    def complete(self, request: LLMRequest) -> LLMResponse: ...
# 没有任何内置实现，开箱即用失败

# ✅ 正例：协议 + 内置默认实现，用户可覆盖
class LLMPort(Protocol): ...
class OpenAICompatLLM(LLMPort): ...   # 内置默认
registry.register(OpenAICompatLLM(...))  # 用户可替换为自定义实现
```

## 五、工程实践

### 规则 10：测试驱动开发，避免功能断点

新模块按"红灯 → 绿灯 → 重构"推进：先写失败测试，再写最小实现使测试通过。上线前必须确认本模块与既有模块**真正联通**，不能出现功能断点。

**要求**：
- 每个新行为先有失败用例，再写实现；禁止先写实现后补测试。
- 涉及跨模块数据流时，必须有**接线测试**：断言上游输出被下游真实消费（而非只测各自单元）。
- 新增/修改协议方法后，检查所有实现者与调用方是否同步更新（含内置默认实现，见规则 9）。
- 设计文档声明的"已实现"必须能在代码与测试中找到对应证据，禁止部分实现冒充完成。
- 测试与门禁全绿方可提交。

```python
# ❌ 反例：只测单元，网关产出从未被下游消费（功能断点）
def test_gateway_emits_event():
    assert gateway.stream_events(...) is not None   # 没验证下游收到

# ✅ 正例：接线测试断言跨模块真实联通
def test_stream_event_reaches_hook_bus():
    events = run_pipeline(...)
    assert any(e.kind is StreamEventKind.USAGE for e in bus.events)
```

### 规则 11：设计承诺反向闭包核对（防"协议有、实现无"的假完成）

规则 9/10 要求默认实现与接线测试，但 R5 曾出现"协议 + 门面 + 测试 fake 三件套冒充完成"——
`MCPTransport` 协议与 `MCPManager` 门面齐全、测试全绿、覆盖率 100%，却没有任何能连 server 的
stdio/http 客户端。根因是**只做逐点实现，没有拿设计承诺逐行反向验收**。本规则把反向核对固化为强制流程。

**要求**：
- 模块开发完成后，必须拿设计的四份承诺清单逐行反向核对，每行给出**代码行号证据**：
  1. §1 职责「做」清单的每一项；
  2. §6 可插拔表的每个注入点 × 四要素（协议 / 默认实现 / 替换入口 / 履约校验）；
  3. §9 功能验证矩阵每个用例 ID 对应的测试文件**真实存在**且测的是真实实现；
  4. 总设计附录 B.1.2 归属本模块的每一行默认实现。
- **判定纪律**（缺一即不得标"已实现"）：
  - `tests/**` 的 fake 不算默认实现；只有协议 + 门面而无真实后端实现，不算兑现"默认 X"承诺；
  - 测试全绿、覆盖率 100% 只证明 fake 闭环自洽，不能替代生产路径真实现 + 装配层接线的验收；
  - 拿不出代码行号证据的条目一律维持"待实现"，禁止部分实现冒充完成。
- 模块必须维护一份**缺口活清单**（如 `.workbuddy/specs/R5-GAP-LIST.md`）：缺口 ID / 设计位置 /
  代码证据 / 归属 / 验收标准 / 状态 / 完成证据（行号），逐项可勾销；跨模块归属（如 R5 依赖 R9）
  只登记不越界实现。
- 对"用户可注入 X"的设计表述必反问：**框架默认 X 在哪？** 若答案是"用户自己提供"，
  直接判违反规则 9，不得以文档措辞敷衍。

```python
# ❌ 反例：协议 + 门面 + fake，测试绿就宣称完成（R5 MCP 的真实教训）
class MCPTransport(Protocol): ...           # 协议有
class MCPManager: ...                        # 门面有，委托注入的 transport
# 测试注入 FakeTransport → 全绿；但没有 StdioMCPTransport/HttpMCPTransport → 开箱连不上任何 server

# ✅ 正例：四要素齐全且逐行有行号证据
# 协议: hooks/protocols.py MCPPort；R5 MCPTransport
# 默认实现: ports/adapters/mcp.py StdioMCPTransport + HttpMCPTransport（真 JSON-RPC）
# 替换入口: MCPManager(registry, transport) 构造注入
# 履约校验: PORT_PROTOCOLS["mcp"] isinstance + 接线测试断言真 transport 被消费
# 反向核对: R5-GAP-LIST.md G01 标 ✅ 且填了 ports/adapters/mcp.py:<行号>
```

## 落地示例（R3/R4 合规重构，2026-11-17）

R3/R4 初版曾在规则 5/6 上不合规（裸魔法串比较、散落 `ctx.meta.get`），后按本规则重构并将检查固化进门禁：
- **规则 5 落地**：退避 `Jitter`、超限 `_ExceedPolicy`、killswitch `_KillScope`、JSON type `_JsonType`、
  输出模式 `_OutputMode` 均为 `str, Enum`；每个带 `coerce()` 对未知值显式回退到安全成员。
  R1 跨层裁决对齐用下划线私有枚举（见 `runner.py:_VerdictAction`），不 import 上层。
- **规则 6 落地**：`src/harness/_ctxview.py` 是 R3/R4 的动态读取**唯一边界**——
  `coerce_ctx(HookCtx)` / `coerce_port_ctx(PortCtx)` 一次读取 meta/payload 并归名为 frozen slots 具名视图，
  下游插件只做属性访问；`router.py:_coerce_route` 是 payload 的局部边界。
  唯一例外是装配期对鸭子插件的 `getattr(h, "priority")`，已在代码注释标注"规则 6 例外"。
- **规则 3 落地**：JSON Schema 形态由外部决定，统一用 `DynamicValue` 具名别名，不再散落裸 `Any`。
