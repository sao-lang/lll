# 七维审查判据与典型反例

每个维度给出：**看什么** / **典型反例** / **怎么判级别**。

---

## 1. 正确性

**看什么**：逻辑在所有分支上是否成立，尤其是边界值。

**边界值清单**（逐个过）：空输入 / 单元素 / 最大值 / 0 / -1 / 空字符串 /
空集合 / 超长输入 / 相同元素 / 已排序与逆序。

**典型反例**：

```python
def average(xs):
    return sum(xs) / len(xs)        # 空列表 → ZeroDivisionError
```

```go
if i := strings.Index(s, sep); i >= 0 {
    part := s[:i]                   // 只处理了命中的分支，未命中被静默跳过
}
```

**级别判定**：会抛异常 / 返回错值 → **Blocker**；
只在极端输入下才触发且概率极低 → **Should**。

---

## 2. 错误处理

**看什么**：失败路径有没有被吞掉。

**典型反例**：

```python
try:
    do_thing()
except Exception:
    pass                            # 吞掉一切，包括 KeyboardInterrupt
```

```js
fetch(url).then(r => r.json())      // 没有 catch，rejection 静默
```

**判据三问**：

1. 空 catch / 只打日志不处理 → 至少要说明为什么可以吞
2. 捕获太宽（`except Exception` / `catch (e)`）→ 会把不该吞的也吞了
3. 错误信息里有没有**上下文**（哪个 id、哪个文件），否则排障时是盲的

**级别判定**：吞掉会导致数据不一致或静默失败 → **Blocker**；
只是日志不够 → **Should**。

---

## 3. 并发与时序

**看什么**：共享可变状态有没有保护；有没有检查与使用之间的时间差（TOCTOU）。

**典型反例**：

```python
if key not in cache:                # 检查
    cache[key] = expensive()        # 使用 —— 中间有窗口
```

```go
go func() {
    results = append(results, r)    // 多个 goroutine 同时 append，无锁
}()
```

**判据**：先找出所有**共享可变状态**，再看每次访问有没有一致的同步策略。
「读多写少」也不能想当然 —— 只要有写，就要有保护。

**级别判定**：会导致数据竞争或状态错乱 → **Blocker**。

---

## 4. 资源生命周期

**看什么**：打开的东西有没有关；有没有无界增长的容器。

**典型反例**：

```python
f = open(p)                         # 没有 with
conn = get_conn()                   # 没有 finally / context manager
```

```js
const seen = new Set()              // 长生命周期服务里永不清理 → 内存泄漏
```

**判据**：文件 / 连接 / 锁 / 定时器 / 订阅，每打开一处就找对应的释放点，找不到就是问题。

**级别判定**：泄漏会累积到耗尽 → **Blocker**；单次短任务里没关 → **Should**。

---

## 5. 性能

**看什么**：循环里的重活、N+1 查询、无界数据结构、不必要的拷贝。

**典型反例**：

```python
for row in rows:                    # N+1：每行一次查询
    row.user = db.get(row.user_id)
```

```python
s = ""
for part in parts:
    s += part                       # 反复拷贝，O(n²)
```

```sql
SELECT * FROM huge_table            -- 只需要 3 列却全取
```

**判据**：先找循环，再看循环体里有没有 IO / 查询 / 大对象拷贝 / 字符串拼接。

⚠️ **不要凭感觉报性能问题** —— 没有数据量级就说「可能慢」是无效结论。
要么给出量级估算（循环 N 次 × 单次 10ms = N×10ms），要么标注「需实测」。

**级别判定**：有明确量级且会超时 → **Blocker**；只是次优 → **Should**。

---

## 6. 安全与数据

**看什么**：外部输入是否可信；敏感信息是否不当落地。

**典型反例**：

```python
os.system(f"convert {user_input}")  # 命令注入
cursor.execute(f"SELECT * FROM t WHERE id={uid}")   # SQL 注入
```

```python
logger.info(f"request from {phone} with id_card={id_card}")  # 敏感信息进日志
```

**判据**：

1. 所有外部输入（请求参数、文件、环境变量、第三方响应）默认不可信
2. 拼接进命令 / SQL / 模板 / 路径的一律要转义或参数化
3. 手机号、证件号、住址、凭据类字段不得进日志与错误上报

**级别判定**：可注入 / 敏感信息泄露 → **Blocker**，且要说清影响面。

---

## 7. 可维护性

**看什么**：半年后别人改得动吗。

**典型反例**：

- 一个函数 300 行，中间 6 层缩进
- 同一段逻辑复制了 3 份
- 硬编码的地址、阈值、开关散落各处
- 命名与实际行为相反（`get_user` 里写了库）

**判据**：

1. 函数是否只做一件事（能不能用一句话说清它在干什么）
2. 重复是否达到 3 次以上（2 次不急着抽，3 次才抽）
3. 常量有没有名字 —— 出现两次以上的字面量就该提取

⚠️ 这一维**绝大多数是 Nit**，只有「命名与行为相反」「复制了 3 份且已产生不一致」
才升级到 Should。

---

## 使用提醒

- 七维不是七道题，是七个**搜索方向** —— 每维的目标是找到 0~3 条具体结论
- 一维扫完没有任何发现是**正常结果**，不要为了凑数硬报
- 同一处问题只报一次，选它最严重的那个维度归位
