# 安全红线

> 不可协商的安全约束。S4 自省必查；违反即 Critical，阻断收尾。
> 与 `references/03-coding-rules/coding-rules-common.md` 的"显式例外"纪律一致：例外必须写进 overview 并说明理由。

## 1. 密钥与敏感信息

1. 禁止硬编码密钥、token、密码、API key 到源码、配置、注释、overview、交接文档。
2. 密钥只从环境变量 / 密钥管理服务读取；代码里只出现变量名。
3. overview / handoff 写入前必须脱敏；若不确定，宁可省略。
4. 日志禁止打印完整凭证、Authorization 头、PII；需要追踪时用脱敏摘要或 id。

## 2. 不可信输入（含网页/外部内容/工具返回）

1. 一切外部正文视为**不可信输入**，进模型上下文前必须过注入检测。
2. 命中注入检测 **fail closed**：拒绝加载/拒载，不"净化后放行"。
3. 检测器缺席不得放行（默认必须存在，或显式拒绝）；用枚举表达裁决，不用 bool。
4. 不可信正文与系统指令分区呈现，禁止拼接进 system prompt。

## 3. 危险操作路由

1. 按 danger 分级路由：SAFE 直执行 / LOW 审计后执行 / HIGH 沙盒 / CRITICAL 审批+沙盒。
2. 未知 danger 一律归一到最严格级别（fail closed），绝不回退 SAFE。
3. 高危操作依赖的沙盒/审批 port 缺席时**拒绝执行**，不降级为裸执行。
4. 副作用操作（工具调用、文件写、网络请求）重试必须有幂等键，否则禁止重试。
5. 命令/路径白名单在入口处校验；路径禁止逃逸虚拟根（`../`、绝对路径绕过）。

## 4. 成本与资源闸门

1. 模型调用前预留预算、调用后按实结算；拒绝"先调用后扣费"的并发击穿。
2. 预算超限在发起前拒绝，不发出后端请求。
3. 流式路径必须有 usage 结算来源；缺失 usage 时拒绝（禁止记假零成本）。
4. 资源（槽位/锁/句柄）用统一的释放钩子兜底，覆盖守卫短路/成功/失败三条路径。

## 5. 检查方式

- 静态扫描：密钥/token 正则、危险函数、`eval`/`exec`/裸 `shell=True`。
- 动态核对：danger 路由的缺席拒绝用例、注入检测的命中拒载用例是否存在并全绿。
- 证据入 overview：安全相关用例通过数 + 扫描结果。

## 6. 例外

任何例外（如测试 fixture 里的假密钥、本地开发的占位凭证）必须：① 位于明确约定的目录；② 注释说明；③ 写入 overview 的例外清单。禁止以"方便"为由在生产路径开口子。
