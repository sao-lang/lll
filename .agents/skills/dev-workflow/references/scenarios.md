# 六场景详细流程

> 每个场景是一段"主控归属 + 加载项 + 禁止项 + 下一步"的明确指令。
> S0（会话开始）与收尾的 overview 写入对所有场景通用。

## 通用前置（所有场景必做）

1. 建 overview：`overviews/YYYY-MM-DD/YYYYMMDD-HHMM-主题.md`（见 `overview.md`）。
2. 读上次 handoff（若有）：定位上次 suggested skills 与未完成项。
3. 场景路由声明：向用户说清"本轮场景 / 加载哪些 skill / 禁止项 / 下一站"。

## 场景 1 · 项目初始化

- **委托内核**：`brainstorming` → `writing-plans`，**到计划为止，不写业务代码**。
- **本外壳额外**：技术选型拷问（`grill-design`）；建 overviews 目录；编码规则文件就位。
- **禁止**：禁止在规格未确认前生成实现代码；禁止引入未选型的依赖。
- **下一站**：用户确认设计 → 进入"项目开发"场景。

## 场景 2 · 项目开发

- **委托内核**：全程 7 步（brainstorm → worktree → plan → subagent → TDD → code-review → finish）。
- **本外壳额外**：S0/S4；S3 加挂 ponytail（代码精简）+ caveman（输出精简）+ coding-rules。
- **禁止**：无失败测试不写实现；魔法字符串不具名不提交；S4 未过不进 review。
- **下一站**：全绿后 finish → 写 overview + handoff。

## 场景 3 · 项目迭代

- **委托内核**：`brainstorming`（轻）→ `writing-plans` → TDD → code-review。
- **本外壳额外**：影响面分析（列出受影响模块 / 调用链 / 契约）；回归检查清单。
- **禁止**：禁止在未列影响面前改动；禁止破坏既有公共契约（除非规格明确要求）。
- **下一站**：回归测试全绿 → review → 收尾。

## 场景 4 · 项目重构

- **委托内核**：TDD 锁行为（先补全行为测试）→ code-review → finish。
- **本外壳额外**：ponytail 砍复杂度（YAGNI 七级梯）；变更前后行为等价性证据。
- **禁止**：**禁止夹带新功能**；禁止在无测试保护下改结构；禁止扩大 diff 到无关代码。
- **下一站**：行为等价 + 全绿 → review → 收尾。

## 场景 5 · 解 bug

- **委托内核**：`systematic-debugging`（4 阶段根因法）→ TDD 写复现测试 → code-review。
- **本外壳额外**：根因台账（现象 / 假设 / 证据 / 结论）；回归证据（复现测试先红后绿）。
- **禁止**：禁止未定位根因就改代码（猜改）；禁止只修表象不加复现测试。
- **下一站**：复现测试转绿 + 无新回归 → review → 收尾。

## 场景 6 · 拷问代码 / 设计（纯只读）

- **不委托工程内核**：本场景不改代码。
- **本外壳主导**：
  - 拷问设计：加载 `grill-design` / `grill-me`，输出设计树 + 未决假设清单。
  - 拷问代码：加载 `code-quality-review`（七维）+ 缺口台账法（功能遗漏 / 功能断点 / 覆盖盲区）。
- **禁止**：禁止在拷问场景修改任何生产代码；禁止把"发现问题"变成"顺便修了"。
- **下一站**：输出结构化问题清单 → 用户决定是否转入"项目迭代 / 重构 / 解 bug"场景。

## 缺口台账法（S4 自省专用，市场 skill 不覆盖）

逐条核对，每条需拿证据（文件:行号 / 测试输出 / 覆盖率），拿不出证据不得标完成：

1. **功能遗漏**：设计文档 / 需求清单的每条承诺，代码里是否有对应实现？
2. **功能断点**：模块内部的"接口就绪"是否真的被装配层调用？（重点查 composition root、dispatch/call 接线、hook 触发者）
3. **测试覆盖率**：是否达到项目阈值？未覆盖的是否为关键路径？
4. **通过率**：测试全绿？有无 flaky / skip / xfail 掩盖？
5. **规则符合**：魔法字符串、注释完整性、类型明确、长度基线是否达标（linter 退出码为证据）。

台账写入 overview 的"验证结果"一节，失败项列"未完成项与下一步"。
