## A. 系统性问题（跨多份文档、同一根因，优先修）

### A1 [Blocker] AOPContainer 构造与方法名存在三套互斥写法，源码只有一套
- 源码真相：`src/aop/container.py:55-61` = `__init__(self, core, *, registry=None, bus=None)`（core 必填位参）；方法只有 `as_call()`(:311) / `run_invocation()`(:307) / `register()`(:105)，**无 `call()`、无 `invoke()`**。
- 文档错版：
  - `R2-插件总线与协议.md:146` `AOPContainer(registry, bus)` + `:152` `def call(self) -> CallFn`
  - `AGENT-总设计.md:609-612` `register(role, enhancer)` + `invoke(inv)`
  - `R3-可靠性.md:141` `AOPContainer.call`
  - `R4-模型与推理.md:299` `AOPContainer(reg=reg, bus=bus)`；`:304` `Runner(call=container.call(gw.as_call()), ...)`
- 建议：全部统一为 `AOPContainer(core=gw.as_call(), registry=reg, bus=bus)` + `as_call()`；补充标准入口 `ModelCapability.container()`（源码 `capability.py:89-95` 已有，文档未提）。

### A2 [Blocker] 自造符号 `NoticePhase`（源码为 `LifecyclePhase`）
- `R2-插件总线与协议.md:158/163/173/271/341` 全篇用 `NoticePhase`；源码 `src/hooks/lifecycle.py:30` 定义的是 `LifecyclePhase`，`__all__` 无 `NoticePhase`，门禁 `tests/tools/gate_check.py:63` 检查的是 `LifecyclePhase` + `PHASE_COUNT`。
- 建议：`NoticePhase` → `LifecyclePhase`，门禁符号表同步（补 `LifecyclePhase`/`PHASE_COUNT`）。

### A3 [Blocker] `Capability.install` 签名三参 vs 源码两参/一参（跨 R2/R3/R4/R5）
- 权威协议 `src/hooks/types.py:56` = `install(self, container: object, reg: Registry) -> None`（两参，无 bus）。
- 源码实现：`tools/capability.py:74` = `install(self, reg)`（一参）；`resilience/capability.py:52` = `install(self, container, reg=None) -> AOPContainer`；`model/capability.py:52` = `install(self, container=None, reg=None) -> Registry`。
- 文档错版（均写三参含 bus）：R2:182 / R3:374 / R4:258 / R5:285；AGENT-总设计:628。
- 建议：以权威协议为准统一为两参；若确需 bus，走 `LifecycleBus.subscribe()` 插件路径，不往 install 加参。

### A4 [Blocker] CallFn 单参 vs 双参
- 源码 `src/runtime/types.py:694` = `Callable[[Effect, DynamicValue], Awaitable[Result]]`（双参）；runner.py:282 实调 `self._call(effect, ctx)`；aop/container.py:311 `as_call()` 产出双参。
- 文档错版：`R1-核心运行时.md:172` = `Callable[[Invocation], Awaitable[Result]]`（单参），`:185-188` 示例 `await call(inv)`；AGENT-总设计:475 正确（双参）。
- 建议：R1 改双参；删除"Runner 直接构造 Invocation/build_meta"的示例（`:187`，源码 runner.py 无 Invocation import，build_meta 全仓 0 命中）——这是**依赖倒置回退**，Invocation 应由装配层 as_call() 构造。

### A5 [Major] Invocation 声明 frozen + Mapping，源码为可变 dict
- 文档 R1/R2/R3/R4 + AGENT-总设计:272 均写 `@dataclass(frozen=True)` + `meta: Mapping`；源码 `src/aop/invocation.py:67-80` = `@dataclass`（可变）+ `meta: dict[str, Any]`，并提供 `write_fault()/write_routing_target()` 原地写入方法。
- 影响：设计宣称的"Refiner 产新 Invocation 不改状态""Notice 只读投影"前提不成立。
- 建议：统一口径——改设计表述为"可变请求期上下文，meta 是具名记录容器，订阅侧只拿只读快照"，裸键赋值改用具名方法。

### A6 [Major] "AOPContainer 与 LifecycleBus 共用同一 Registry"契约无代码载体
- 文档 R2:23/64/172/341 承诺共用同一 Registry 实例；源码 `src/hooks/lifecycle.py:114-123` LifecycleBus 无 registry 参数/属性，`src/aop/container.py:70` 的 registry 仅存不用。规格 P6 要求"两表统一"。
