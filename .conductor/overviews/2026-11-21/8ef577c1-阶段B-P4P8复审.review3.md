## 二、Findings 分级

### Should-1 — Graph.node(Arch) 捕获一次性 generator，二次 compile 违反 D-8 幂等
- 位置：`src/archs/recipes.py:237-238`
- 证据（实测）：`g = Graph().node("a", ToolUse([...])).exit("a")`；`compile()` 第一次产出 `['Invoke:tool', 'Terminate:']`，第二次产出 `['Terminate:']`（Invoke 丢失）。根因：`compiled = program.compile()` 得 generator 对象，`self._nodes[id] = lambda: compiled` 每次返回同一个已耗尽 generator，而非工厂重建。
- 后果：Graph 嵌套 Arch 时 resume/二次编译会得到空 Program（领域 Effect 消失）；直接违反模块 docstring（`recipes.py:7-9`）与 D-8"resume 靠工厂重建、compile 幂等"约束。当前无测试覆盖（`tests/r12/` 仅 `test_tool_layers.py:113` 检查名字存在、`:121-132` 只编译 ToolUse，未测 Graph 嵌套/二次编译）。
- 改法：`node()` 保存 Arch 工厂本身而非其 generator，如 `self._nodes[id] = program.compile`（compile 为无参 bound method 即 ProgramFn）；或在调用时 `lambda p=program: p.compile()`，保证每次 `compile()` 产出新 generator，并补"Graph 嵌套 Arch 二次 compile 等价"用例。

### Should-2 — ToolUse(parallel=False) 丢弃中间工具
- 位置：`src/archs/recipes.py:71`
- 证据（实测）：`ToolUse([t1,t2,t3], parallel=False).compile()` 产出 `['Invoke:t1', 'Invoke:t3', 'Terminate:']`，`t2` 被丢弃（`seq(leaves[0], leaves[-1])` 只取首尾）。
- 后果：非并行模式本应顺序执行全部工具，实际只跑首尾两个，中间工具静默丢失；属架构配方语义缺陷（R12 §6 ①一次性工具调用）。
- 改法：用 `functools.reduce(seq, leaves)` 或循环 `cur = seq(cur, leaf)` 串接全部叶子，补 3 工具顺序用例。

### Should-3 — Handoff 丢弃中间角色
- 位置：`src/archs/recipes.py:201`
- 证据（实测）：`Handoff({'a':..,'b':..,'c':..}).compile()` 产出 `['Invoke:a', 'Invoke:c', 'Terminate:']`，角色 `b` 丢失（`seq(leaves[0], leaves[-1])`）。
- 后果：角色交接链只跑首尾角色，中间交接静默跳过，与"角色交接 seq 串接全部角色"语义不符（R12 §6 ⑧）。
- 改法：同 Should-2，串接全部 `leaves`，补 3 角色用例。

### Nit-1 — Supervisor.join 默认值与 R12 §4 签名不一致
- 位置：`src/archs/recipes.py:168`（`join: Any = None`）vs `docs/02-模块详设/Agent/R12-内置架构与组合.md:88`（`join: JoinStrategy = MajorityVote()`）。
- 后果：默认构造行为与"对外 API 不变"规格有偏差；当前 `join` 未被 `compile()` 消费（`recipes.py:180-181` 仅 `par` 两叶子），无运行期影响，仅签名一致性问题。
- 改法：默认值改为规格约定的 `MajorityVote()`（或明确记录为有意简化并在 R12 §4 同步）。

### Nit-2 — ast_scan 的领域字段归位检查仅覆盖注解形式，漏检方法形式
- 位置：`tests/tools/ast_scan.py:486`（`re.search(rf"^\s+{field}:", ...)`）
- 证据：仅匹配 `field:` 注解声明；若在基础 Port 内声明 `def recall(...)`（方法）不会被该正则捕获。当前基础 Port 实际干净（实测 `hasattr` 为 False，见要点 3），故为防御性覆盖缺口而非已发生违规。
- 后果：未来若有人在 `hooks.MemoryPort` 内加回 `recall` 方法，门禁红线条不会报警。
- 改法：同时匹配 `def {field}\b`（或改用 AST 遍历类体成员），覆盖注解与方法两种声明。
