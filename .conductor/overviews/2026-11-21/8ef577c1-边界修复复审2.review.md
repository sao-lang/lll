### SHOULD-1【Should / B-2 残余缺口】真实 `after_tool` 首步被误标 `seq_synthetic=True`，seq 落回进程计数

**证据**（自编探针，`port=tool`）：
```
R1 Event.seqs=[0,1] len=2
env type=after_tool   seq=1 synthetic=True    ← 真实 R1 驱动的通知，却被标合成
env type=session_end  seq=2 synthetic=False
```
**根因**：`after_tool` 在 `runner.py:343-345` 于 **step 内、`_execute` 中**发出，此时当前步的 Event 尚未 append（`runner.py:564` 才 append），`len(session.events)=0`。`R1SeqTracker.current()`（`wiring.py:102-108`）返回 `0`——这其实是该步正在生成的 Event 的合法 R1 seq（下一个 Event 的 `seq=len(events)=0`，`runner.py:551`），但 `publish_notice`（`wiring.py:256-266`）把 `seq<=0` 当作"无序号"，落到 `payload["seq"]`（0），再走 `fallback += 1` → `seq=1, synthetic=True`。
**为何是问题**：红队问"seq_synthetic 是否只在真合成时出现"——答：**否**。真实生产路径（第一步 tool 调用）误标合成且 seq 与 R1 脱钩。AC-5"seq 优先取 Notice 携带的 R1 序号"在该路径未兑现。前轮 B-2 测试用 `port=llm`（不触发 `after_tool`）掩盖了此路径，属同类"选不触发问题的场景验证"的假绿残余。
**修复建议**：`publish_notice` 区分"无 source"与"source 返回 0"——当 `seq_source is not None` 时，`current()==0` 应视为合法 R1 seq=0（不落 fallback、不标 synthetic）；或让 tracker 在 step 内提供"当前步 seq"而非仅 `len(events)`。

### SHOULD-2【Should / 预存缺陷，非本提交引入】`manager().load() → replay_snapshot()` 仍崩，测试用内存 DTO 绕开

**证据**（自编探针，走真实 `rt.checkpoint.manager().load()`）：
```
manager.load -> CheckpointSnapshot version:0.0.0 fingerprint len:64 events:2
initial state messages: () scratch: {}
replay_snapshot -> AttributeError: 'dict' object has no attribute 'effects'
```
**根因**：`CheckpointManager.load()`（`src/harness/durability/checkpoint.py:102-117`）把 `events` 原样返回（R1 快照里的 `_plain` dict），而 `replay_snapshot()`（同文件 `:120-122`）直接喂给 R1 `replay_events`（`src/runtime/fold.py:220-222` 读 `event.effects`），dict 无该属性 → 崩。`wiring.py:284` docstring 声称"终态回放用 replay_snapshot"，但该路径实际不可用。
**归属判定**：`git show c781582:src/api/wiring.py` 确认父提交 `dto.events = tuple(snapshot.get("events") or ())`（同为 plain dict），故**此缺陷在 c781582 即存在，非 8d50cb8 引入**；本轮不阻断合入，但因红队专项问及"R10 replay 路径是否被破坏"而据实报告。`tests/r11/test_wiring.py:139-141` 用 `mgr.snapshot(..., tuple(session.events))`（真实 Event 对象）在内存构造 DTO 后回放，**未覆盖 `load()` 读回再回放的生产路径**，故长期漏检。
**修复建议**：`CheckpointManager.load()` 用 `_effect_from_plain`/`revive` 重建 Event 对象后再放进 DTO，或 `replay_snapshot` 兼容 dict 事件；补一条 `save → manager().load() → replay_snapshot` 的失败测试。

### NIT-1【Nit】审计保留 key `__audit__:` 无命名空间校验，特殊 session id 可污染回放

**证据**（自编探针）：若业务 session id 恰为 `__audit__:x`，审计 append（`wiring.py:73,128-139`）会与业务 checkpoint 共用 key：
```
after audit append snapshot events: [{'biz':1}, {audit event...}]
replay_audit_events -> [('',''), ('w','a')]   ← 业务事件被重建为空壳 AuditEvent
```
常规 id 不受影响；仅保留前缀被业务占用时产生空壳审计事件。建议在 `key_of()`/`append` 或 session id 入口校验禁止 `__audit__:` 前缀，或改审计专用 store/键空间。

### NIT-2【Nit】`R1SeqTracker` 单实例 + 覆盖式 `bind_session`，并发/嵌套会话 seq 归属可能被串

`assemble_runtime`（`runtime.py:143`）只创建一个 tracker，`bind_session`（`runtime.py:67-68,73-74`）每次覆盖 `_session`。同一 runtime 并发跑多会话时，`current()` 返回最后绑定会话的 `len(events)`，投影 seq 会串到错误会话。当前 Spawn 子会话不经 `AgentRuntime.run`（不重新 bind），但主会话并发场景存在理论风险。建议按 session_id 维护映射或每次投影以 notice.session_id 校准。
